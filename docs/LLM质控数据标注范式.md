# 星衍AI放射质控 — LLM 数据标注范式

> 本文档定义 LoRA 微调 Qwen3-3B 所需的质控数据标注规范。
> 格式直接对齐现有 `src/engine.py:Finding` + `server/schemas.py:FindingOut`，
> 微调产出的模型输出可零改动接入 `server/deps.py:_run_qc()` 管道。

---

## 一、数据标注总览

### 1.1 一条标注 = 一条 "输入→输出" 对

```
输入：放射报告原文 + 元数据
输出：检出问题列表（List[Finding]）
```

### 1.2 输入格式

```json
{
  "instruction": "你是一名放射科质控专家。请分析以下放射检查报告，找出所有质控缺陷，按标准格式输出。",
  "report": "双肺纹理清晰，走行自然，未见明显实质性病变。双侧肺门不大，纵隔居中，未见肿大淋巴结。心脏大小形态正常。双侧胸膜未见增厚，胸腔未见积液。所示骨骼未见异常。肝内见类圆形低密度灶，边界模糊，增强后未见明显强化，考虑囊肿可能。\n\n诊断意见：右肺下叶结节，建议定期复查。",
  "meta": {
    "patient": "王某某",
    "gender": "女",
    "age": "45",
    "modality": "CT",
    "applied_site": "胸部"
  }
}
```

### 1.3 输出格式（直接对齐 FindingOut）

```json
{
  "findings": [
    {
      "rule_id": "R5-CONSISTENCY",
      "error_type": "矛盾",
      "severity": "high",
      "message": "描述段称'未见明显实质性病变'，但结论段写'右肺下叶结节'，属于描述正常/结论异常跨段矛盾",
      "snippet": "未见明显实质性病变",
      "span": [12, 24],
      "suggestion": "核对描述与结论的一致性，如确认结节存在，则描述段应补充结节描述"
    },
    {
      "rule_id": "R6-SITE",
      "error_type": "漏写",
      "severity": "medium",
      "message": "检查部位为胸部，但肝脏病灶描述('肝内见类圆形低密度灶')未在检查部位描述中体现",
      "snippet": "肝内见类圆形低密度灶",
      "span": [80, 94],
      "suggestion": "检查部位描述应涵盖扫描范围内所有阳性发现"
    }
  ]
}
```

## 二、标注 Schema 字段说明

### 2.1 字段定义

| 字段 | 类型 | 必填 | 说明 | 来源 |
|------|------|------|------|------|
| `rule_id` | `str` | ✅ | 对应 R1–R22 规则编码 | 与 `engine.py` 规则 ID 完全一致 |
| `error_type` | `str` | ✅ | 错误类型中文名 | 从现有枚举值中选取 |
| `severity` | `str` | ✅ | `"high"` / `"medium"` / `"low"` | 与 `SEVERITY_WEIGHT` 一致 |
| `message` | `str` | ✅ | 质控缺陷描述，说明为什么这是一个缺陷 | 自然语言，科室可读 |
| `snippet` | `str` | 推荐 | 报告中导致缺陷的具体片段 | 抽取原文，助定位 |
| `span` | `list[int]` | 推荐 | `[start_char, end_char]`，在 report 中的字符偏移 | 标注时手动计算 |
| `suggestion` | `str` | 推荐 | 修改建议 | 自然语言 |

### 2.2 rule_id 完整列表（R1–R22）

| 编码 | 规则名称 | 引擎分类 | 语义/规则 | LLM 微调预期增益 |
|------|---------|---------|-----------|----------------|
| R1-GENDER | 性别与检查部位一致性 | 规则 | 规则 ✅ | 低（规则已够） |
| R2-LATERALITY | 侧别一致性 | 规则 | 规则 ✅ | 低 |
| R3-SCORE | 评分规范 | 规则 | 规则 ✅ | 低 |
| R4-UNIT | 单位规范 | 规则 | 规则 ✅ | 低 |
| R5-CONSISTENCY | 描述-结论一致性 | **语义** | 规则仅部分覆盖 | **🔥 高增益** |
| R6-SITE | 检查部位描述覆盖 | **语义** | 规则仅部分覆盖 | **🔥 高增益** |
| R7-INTERNAL | 内部参照一致性 | 规则 | 规则 ✅ | 中 |
| R8-TYPO | 错别字 | 规则 | 规则 ✅ | 中（字典型） |
| R9-CONFLICT | 自相矛盾 | **语义** | 规则仅部分覆盖 | **🔥 高增益** |
| R10-TEMPLATE | 模板缺失 | 规则 | 规则 ✅ | 中 |
| R11-ABNORMAL / R11-SIDE / R11-GENDER | 异常描述逻辑 | 规则 | 规则 ✅ | 低 |
| R12-SENTENCE | 语句规范 | **语义** | 规则仅部分覆盖 | **🔥 高增益** |
| R14-COUNT / R14-NATURE / R14-NORMAL / R14-SIDE | 数量/性质/正常/侧别 | 规则 | 规则 ✅ | 低 |
| R15-NORMAL / R15-PRESENCE / R15-SIDE | 正常描述 | 规则 | 规则 ✅ | 低 |
| R16-FOLLOWUP | 随访建议 | 规则 | 规则 ✅ | 中 |
| R17-PERREGION | 逐部位器官比对 | 规则 | 规则 ✅ | 中 |
| R18-COVERAGE | 报告完整性 | **语义** | 规则仅部分覆盖 | **🔥 高增益** |
| R19-HOMOPHONE | 形近字/同音字 | 规则 | 规则 ✅ | 低（字典型） |
| R20-TEMPLATE | 模板完整度 | 规则 | 规则 ✅ | 低 |
| R21-GENDER | 性别检查部位 | 规则 | 规则 ✅ | 低 |
| R22-SIZE / R22-UNIT | 尺寸/单位 | 规则 | 规则 ✅ | 低 |

**标注策略：优先标注「语义类」规则**（R5、R6、R9、R12、R18），这些是规则引擎的短板，也是 LLM 微调最大的增量价值。

## 三、标注规则详解（按优先级）

### 🟥 优先级 A：语义类（LLM 核心增量）

#### R5-CONSISTENCY — 描述与结论一致性

**检查：** 描述段的内容与结论段是否矛盾。

**典型场景：**
| 描述段 | 结论段 | 判断 |
|--------|--------|------|
| "未见明显实质性病变" | "右肺下叶结节" | ❌ 矛盾，high |
| "双肺纹理增粗、模糊" | "双肺未见异常" | ❌ 矛盾，high |
| "肝内多发低密度灶" | 结论未提及肝脏 | ⚠️ 遗漏，medium |

**标注示例：**
```json
{
  "rule_id": "R5-CONSISTENCY",
  "error_type": "矛盾",
  "severity": "high",
  "message": "描述段描述'未见明显实质性病变'，但结论段提示'右肺下叶结节'，两者矛盾",
  "snippet": "未见明显实质性病变",
  "span": [12, 24],
  "suggestion": "请核实结节是否存在；如确认存在，描述段应补充结节大小、形态、密度、边界等信息"
}
```

---

#### R6-SITE — 检查部位/器官描述覆盖

**检查：** 报告描述是否覆盖了扫描范围内所有应描述的器官/部位。

**典型场景：**
| 检查部位 | 描述内容 | 判断 |
|---------|---------|------|
| 胸部CT | 只描述了肺，没有描述纵隔、心脏、胸膜 | ❌ 漏写胸膜，medium |
| 上腹部CT | 只描述了肝脏，没有描述胆囊、胰腺、脾脏、肾脏 | ❌ 漏写多个器官，high |
| 头颅CT | 描述了脑实质，但没有描述脑室、脑沟、颅骨 | ⚠️ 漏写颅骨，low |

**标注示例：**
```json
{
  "rule_id": "R6-SITE",
  "error_type": "漏写",
  "severity": "medium",
  "message": "检查部位为胸部CT，但描述中未提及双侧胸膜和胸腔情况",
  "snippet": "",
  "span": [0, 0],
  "suggestion": "补充胸膜、胸腔的描述，例如'双侧胸膜未见增厚，胸腔未见积液'"
}
```

---

#### R9-CONFLICT — 自相矛盾

**检查：** 同一份报告内部存在逻辑上无法同时成立的两处描述。

**典型场景：**
| 描述A | 描述B | 判断 |
|-------|-------|------|
| "右肺上叶见一结节" | "双肺未见明确结节" | ❌ 矛盾，high |
| "肝脏大小形态正常" | "肝内多发占位" | ❌ 矛盾，high |
| "左肾萎缩" | "双肾大小形态正常" | ❌ 矛盾，high |

**标注示例：**
```json
{
  "rule_id": "R9-CONFLICT",
  "error_type": "矛盾",
  "severity": "high",
  "message": "描述段称'右肺上叶见一结节'，但同一段后又写'双肺未见明确结节'，前后矛盾",
  "snippet": "右肺上叶见一结节，双肺未见明确结节",
  "span": [30, 52],
  "suggestion": "确认结节是否存在，统一描述"
}
```

---

#### R12-SENTENCE — 语句规范性

**检查：** 报告语句是否存在语法问题、歧义、模糊表述、不符合医学书写规范。

**典型场景：**
| 原文 | 问题 | 判断 |
|------|------|------|
| "右肺有东西" | 用词模糊 | ❌ 不规范，medium |
| "肺纹理增多增粗模糊" | 缺少逗号/顿号，语意不清 | ❌ 不规范，low |
| "患者可能觉得是炎症" | 不应使用揣测语气 | ❌ 不规范，medium |
| "大致同前，变化不著" | 缩写不规范，非标准术语 | ❌ 不规范，low |

**标注示例：**
```json
{
  "rule_id": "R12-SENTENCE",
  "error_type": "不规范",
  "severity": "medium",
  "message": "使用非规范表述'右肺有东西'，应使用标准影像学描述术语",
  "snippet": "右肺有东西",
  "span": [15, 20],
  "suggestion": "改为'右肺见结节状高密度影'或根据实际所见描述"
}
```

---

#### R18-COVERAGE — 报告完整性

**检查：** 报告是否完整覆盖了放射报告应有的结构要素。

**典型场景：**
| 缺失内容 | 判断 |
|----------|------|
| 缺少检查方法/扫描参数 | ❌ 缺失，medium |
| 缺少与旧片比较 | ⚠️ 缺失，low（非必须） |
| 结论段缺少对阳性发现的总结 | ❌ 缺失，medium |
| 缺少对建议随访的描述（当有阳性发现时） | ❌ 缺失，medium |

**标注示例：**
```json
{
  "rule_id": "R18-COVERAGE",
  "error_type": "漏写",
  "severity": "medium",
  "message": "报告描述了右肺下叶结节，但未给出随访建议",
  "snippet": "",
  "span": [0, 0],
  "suggestion": "添加随访建议，如'建议定期复查，必要时进一步检查'"
}
```

---

### 🟨 优先级 B：规则强化类（LLM 辅助）

#### R8-TYPO — 错别字

**模型擅长但规则引擎也擅长，但 LLM 可覆盖规则未收录的错别字。**
无需过多标注，靠规则引擎兜底即可。

**标注示例：**
```json
{
  "rule_id": "R8-TYPO",
  "error_type": "误写",
  "severity": "low",
  "message": "'末见'应为'未见'",
  "snippet": "末见",
  "span": [5, 7],
  "suggestion": "改为'未见'"
}
```

---

#### R16-FOLLOWUP — 随访建议

**标注示例：**
```json
{
  "rule_id": "R16-FOLLOWUP",
  "error_type": "随访",
  "severity": "medium",
  "message": "报告阳性发现(右肺下叶结节)未给出随访建议",
  "snippet": "右肺下叶结节",
  "span": [120, 127],
  "suggestion": "建议添加'建议定期复查，3-6个月后复查CT观察变化'"
}
```

---

### 🟩 优先级 C：规则类（LLM 可不涉及）

R1、R2、R3、R4、R7、R10、R11、R14、R15、R17、R19、R20、R21、R22

**这些规则可用现成的 RuleEngine 处理，LLM 微调可跳过或少量覆盖。**
标注时遇到可标注，但不作为主要精力投入。

## 五、标注质量控制

### 5.1 一致性要求

| 维度 | 要求 |
|------|------|
| rule_id | 必须从 R1–R22 列表中选取，不得自行发明 |
| error_type | 必须从现有错误类型枚举中选取 |
| severity | 固定：high / medium / low，参考规则引擎权重 |
| snippet | 必须是 report 原文的精确子串，不能修改 |
| span | 严格对应 snippet 的字符偏移，snippet 为空时 span=[0,0] |

### 5.2 标注优先级

```
第一轮（核心 300 条，覆盖语义类）：
  R5-CONSISTENCY  × 60 条
  R6-SITE         × 50 条
  R9-CONFLICT     × 40 条
  R12-SENTENCE    × 50 条
  R18-COVERAGE    × 40 条
  R16-FOLLOWUP    × 30 条
  R8-TYPO         × 30 条
  ────────────────
  合计 ≈ 300 条

第二轮（扩展 500 条，覆盖全部规则）：
  在 300 条基础上加入 R1-R4/R7/R10-R11/R14-R15/R17/R19-R22
  并增加多缺陷组合场景（同一份报告多个 rule_id）
```

### 5.3 标注难度分级

| 级别 | 说明 | 适合谁标 |
|------|------|---------|
| ★☆☆ | 错别字、单位错、性别不一致 | 任何熟悉放射报告的人 |
| ★★☆ | 侧别漏写、部位漏写、模板缺失 | 有经验的报告录入员 |
| ★★★ | 描述-结论矛盾、自相矛盾、语句规范 | 放射科医生（标注者） |

## 六、数据量建议

| 目标 | 标注量 | 预期效果 |
|------|--------|---------|
| 最小可用 | 300 条 | 语义类错误有明显改善，但召回率较低 |
| 推荐 | **800 条** | 80% 语义类错误可捕获，输出格式稳定 |
| 理想 | 1500+ 条 | 接近完整规则引擎的召回率，且覆盖语义类 |

## 七、LLM 与规则引擎的协作分工（最终运行时）

```
输入报告
    │
    ├─→ LLMEngine.run()  ← 微调后的 Qwen3-3B
    │     检出 List[Finding]（含语义类 + 部分规则类）
    │
    ├─→ RuleEngine.run()  ← 现有 R1-R22
    │     检出 List[Finding]（确定性规则类）
    │
    ├─→ 合并/去重/交叉校验
    │     - 同一 rule_id + 同一 snippet → 保留一条
    │     - 规则引擎的确定性错误（如 R8-TYPO）覆盖 LLM 的同类判断
    │     - LLM 的语义类错误（R5-CONSISTENCY 等）保留
    │
    └─→ FindingOut → score() → 前端/看板
```
