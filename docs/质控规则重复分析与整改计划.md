### 群集 A · 左右侧矛盾（5 个规则）
| 规则 | 检查对象 | 与群集内其他规则的差异 |
|---|---|---|
| `R2-LATERALITY` | 描述段 ↔ 印象段，同部位族左右互斥 | 仅跨段比 |
| `R11-SIDE` | 信息框侧别（项目/检查部位/申请部位） ↔ 正文仅提对侧 | 输入源是"信息框"，非正文内部 |
| `R14-SIDE` | 检查所见 ↔ 诊断印象，同器官左右矛盾（含英文报告） | 跨段 + 英文 MIMIC/IU-Xray 风格 |

| `R17-PERREGION` | 逐部位 `(器官, 侧别)` 精确比对 | 最精细，区分左右、定位到具体部位 |

## 四、是否"真冗余"的判定

### 4.1 多为有意互补（建议保留）
- **群集 A** 的 5 个规则输入源与防误报策略各异：R2 只看正文跨段、R11-SIDE 引入信息框侧别、R15-SIDE 查单段自相矛盾、R17 精确到 `(器官,侧别)`。它们覆盖"信息来自不同处 / 不同粒度"的矛盾，**不是简单复制**，删任一都会漏检一类场景。
- **群集 B** 的 R1/R7/R11-GENDER/R12 同理：分别处理"元信息性别 vs 器官""段内混用""信息框 vs 正文""句内混用"。

### 4.2 存在"子规则碎片"可考虑归并（第二阶段）
- 群集 C 的 `R11-ABNORMAL` / `R14-NORMAL` / `R17-PERREGION` 三者均查"描述正常而结论异常"，只是兜底层级不同（段级 / 跨段 / 逐部位）。**Finding 键碎片化**，前端展示时用户会看到多条"描述正常结论异常"类告警，观感重复。
- 建议：在**引擎内部**将这三类统一为单一"描述↔结论正常性矛盾"策略（保留多粒度判定，但对外合并为更少的 Finding 类型），**不改变检出能力**。
