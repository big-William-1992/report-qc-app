# 星衍放射质控软件 · 临床效能评价（验证）方案

> 文档性质：**研究者发起的效能评价方案（草案，v0.1）**。用于指导单中心回顾性临床验证研究的实施、统计分析与论文/标书产出。
> 适用产品：星衍放射质控软件（`report_qc_app`）—— 确定性规则引擎 R1–R25 + 可选 LLM 语义层（本地微调 Qwen3-4B LoRA）。
> 目标读者：产品创始人、医院放射科与医务科、方法学/统计人员、未来器械注册申报或论文投稿团队。
> **声明**：本方案中所有样本量数字均为**示例计算**，正式实施前必须依据初勘（pilot）结果重新估算，并经统计学与伦理委员会确认（文中凡不确定处均标注"需与统计/伦理委员会确认"）。

## 0. 摘要

本研究拟对星衍放射质控软件做**两套相互独立**的临床效能评价：

| 编号 | 研究问题 | 主终点 | 设计 |
|---|---|---|---|
| **研究 A** | 确定性规则引擎（R1–R25）相对**人工质控金标准**的检出效能与一致性如何？ | 报告级敏感度/特异度、错误条目级 recall/precision、与金标准的 kappa | 回顾性、连续入组、盲法阅片金标准 |
| **研究 B** | LLM 语义层在**规则漏报区**是否有增量价值？ | 增量召回率（Δrecall）、新增误报率（ΔFP） | 嵌套于 A 的**语义错误富集**子队列 + 逆概率加权 |

**关键方法学立场**：A 与 B 的问题、金标准、分析集与指标**必须分开设计**，禁止把"规则 + LLM"合并成一个指标来汇报；否则无法区分"规则本来就能抓的确定性错误"与"LLM 真正的语义增量"。

**为何必须重做评测（本方案存在的理由）**：仓库现有评测集 `data/qc_sft_eval.jsonl`（200 例 = 91 有错 + 109 正常）的标签是**由规则引擎自身蒸馏/注入得到的银标**。规则链路在该集上 recall 100% / specificity 100%，属**银标自证**，只能用作"引擎行为是否发生意外漂移"的回归护栏，**不能**作为对外临床效能证据（详见 §1.2）。

## 1. 研究背景、目的与假设

### 1.1 背景

星衍放射质控软件对**中文放射科报告**做质量自动核查，由两层构成：

| 层级 | 技术 | 设计定位 | 运行特性 |
|---|---|---|---|
| 第一层 | 确定性规则引擎 R1–R25（性别矛盾、左右侧混淆、评分缺失如 BI-RADS/PI-RADS、计量单位错误、描述-结论矛盾、登记部位不符、内部矛盾、同音/形近错别字、模板合规、逐部位精确比对、部位器官漏写、病灶尺寸术语一致性等） | 硬门禁、可解释、低误报 | 同步，单份约几十毫秒 |
| 第二层 | 可选 LLM 语义层（**本地微调 Qwen3-4B LoRA**，`prompt_mode=ft`） | 抓规则抓不到的**语义级/语境级**问题（随访建议缺失、良恶性与处置建议不匹配、叙事规范等） | 异步，秒级/例 |

部署形态：院内内网或单机，**数据不出院**；支持桌面端（Windows exe）或 Web；具备账号与科室归属、审计日志。反馈闭环：医生在界面点"误报/漏报"→ 写入本机 `feedback.db` → 可导出 JSONL 供精调/评测。

规则编码已覆盖 R1–R25，严重度分为 `high`/`medium`/`low`（评分权重 30/15/5）。人工标注规范见 `docs/LLM质控数据标注范式.md`。

### 1.2 现有评测数据的真实情况与局限（反例，务必如实呈现）

> 本节为**否定性证据**说明：现有数据不足以支撑任何对外效能结论。

**已实测记录（2026-09-30）：**

| 链路 | recall | specificity | 样本量 | 耗时 |
|---|---|---|---|---|
| rules（确定性规则） | **100.0%** | **100.0%** | 91 错 + 109 正常 = 200 | 20s |
| llm（微调 Qwen3-4B LoRA / MLX / `prompt_mode=ft`） | **9.9%** | **100.0%** | 同上 | 479s（≈2.4s/例） |

同 20 例 `prompt_mode` A/B 对照（同一模型）：

| prompt_mode | recall | specificity | 发现数 | 零输出例数 |
|---|---|---|---|---|
| `ft` | 18.2% | 100.0% | 6 | 15/20 |
| `full` | 0.0% | 0.0% | 25 | 0/20 |

**为什么这些数字不能作为效能结论：**

| 问题 | 说明 |
|---|---|
| **银标自证** | 评测集标签由规则引擎自身蒸馏/注入生成 → 规则链路 recall/specificity 必然接近 100%，衡量的是"引擎行为漂移"，不是准确率 |
| **错误类型单一** | 该集错误**几乎全是确定性错误**（错别字 R8-TYPO、左右 R2-LATERALITY、模板/覆盖 R10/R18、同音形近 R19、描述-结论矛盾 R5 等），而 LLM 层的设计目标是抓**规则抓不到的语义级漏报** |
| **目标错配** | 用确定性错误集给"语义补漏器"打分，只测出"LLM 与规则的重合度"，**测不出 LLM 的目标价值** |
| **`full` 模式不可用** | `full` 模式对**每一份**报告都报错（含全部正常报告）并编造不在允许清单内的 `error_type`，已确认为**不可用配置**，不得进入验证 |
| **无人工金标准** | 全流程无资深医师盲法判读，"真错误/假错误"的界定来自规则自身 |

**结论**：现有银标数据仅保留为**回归护栏**（`benchmarks/` 基线），本节之后的所有效能推断，均须基于**人工金标准**的新研究。

### 1.3 研究目的与假设

本研究拆成**两个可分别成立的问题**，各自定义终点、各自可独立发表：

#### 研究 A —— 规则引擎的检出效能与一致性

| 项 | 内容 |
|---|---|
| 目的 | 评价确定性规则引擎（R1–R25）相对人工质控金标准的检出效能、一致性与局限性 |
| 原假设 H0(A1) | 系统报告级敏感度 ≤ 0.60（预设临床可接受下线） |
| 备择假设 H1(A1) | 系统报告级敏感度 > 0.60 |
| 原假设 H0(A2) | 系统与人工金标准的一致性 kappa ≤ 0.40（"一般"以下） |
| 备择假设 H1(A2) | kappa > 0.40 |
| 探索性 | 各错误类型分层敏感度/特异度；假阴性（漏报）与假阳性（误报）的错误类型分布 |

#### 研究 B —— LLM 语义层在规则漏报区的增量价值

| 项 | 内容 |
|---|---|
| 目的 | 在"规则引擎漏报"的错误集合中，评价叠加 LLM 语义层后的**增量召回**与**新增误报** |
| 原假设 H0(B) | LLM 增量召回率 ≤ 0.10（增加 LLM 不能带来有临床意义的补漏） |
| 备择假设 H1(B) | LLM 增量召回率 > 0.10 |
| 关键约束 | 分析**必须限定在规则漏报区**（金标准判定为错误、但规则引擎未报出的条目），不得与规则命中区混合 |
| 次要终点 | 新增误报率（LLM 报出但金标准判为无该错误）；语义错误亚型（随访建议缺失 / 良恶性与处置建议不匹配 / 叙事规范）分层 |

> **措辞要求**：论文与标书中，"检出效能"一词**只**用于研究 A；研究 B 一律使用"增量召回 / 新增误报"表述。

## 2. 研究设计

### 2.1 总体设计

| 维度 | 设计 |
|---|---|
| 类型 | 回顾性、观察性、诊断准确性/一致性研究（系统为"待评价检查"，人工金标准为"参考标准"） |
| 入组方式 | **连续入组**（按报告签发时间顺序），避免"挑好看的报告"带来的选择偏倚 |
| 中心 | 单中心（起步）；多中心作为后续扩展 |
| 阶段 | 阶段一 **初勘（pilot）**；阶段二 **正式研究**（据初勘估算样本量） |
| 报告集合 | 回顾既往已签发报告，只取**文本**（与系统输入一致），不重新采集影像 |

**流程图：**

```
报告池（连续入组）
   │  按纳入/排除标准筛选
   ▼
纳入集合（阶段一：约 100–200 份）
   │
   ├─→ 阶段一 初勘（pilot）
   │      · 估计错误类型分布与各类型检出难度
   │      · 估计 kappa / 敏感度 / 特异度 的粗值，用于正式研究样本量
   │      · 校准 CRF 表字段与阅片流程
   │
   ▼
正式研究集合（连续入组，据初勘估算 N）
   │
   ├─→ 研究 A：全集合 ── 规则引擎 vs 人工金标准
   │
   └─→ 研究 B：规则漏报区富集子队列 ── 规则 vs 规则+LLM
```

### 2.2 纳入标准

| # | 标准 |
|---|---|
| 1 | 本院放射科已签发的**中文**诊断报告（文本可用） |
| 2 | 报告类型属于预先指定的常见类型：CT / MR / DR / 超声 / 钼靶（乳腺）等（**具体类型清单须在方案定稿前与放射科确认**） |
| 3 | 报告具备可解析的元数据：患者性别、检查部位、检查方法（模态） |
| 4 | 报告在系统版本冻结期（§9.5）内产生 |

### 2.3 排除标准

| # | 标准 | 理由 |
|---|---|---|
| 1 | 报告文本缺失、严重截断或无法解析 | 与系统输入不可比 |
| 2 | 非中文报告或中英混杂占比过高 | 超出系统设计范围 |
| 3 | **OCR 来源且质量不可接受**（关键字段不可读/字符错乱率过高） | OCR 噪声会同时污染系统与金标准；**若纳入 OCR 来源，必须单独分层分析**（见 §9.4） |
| 4 | 报告为模板占位/未完成状态（如"待补充"） | 无法判定真错误 |
| 5 | 同一患者同一检查的重复版本（仅保留最终签发版） | 避免重复计数 |
| 6 | 研究团队无法完成盲法判读的特殊类型（如极罕见检查） | 金标准不可靠 |

> **需与统计/伦理委员会确认**：排除标准的最终清单，尤其 OCR 来源报告的处理口径（是否纳入、是否单独分层）。

### 2.4 两个阶段的具体安排

| 项 | 阶段一 初勘（pilot） | 阶段二 正式研究 |
|---|---|---|
| 样本量 | 约 **100–200 份**（建议含 ≥50 份含错报告） | 据初勘估算（见 §3；示例约 300–400 份） |
| 目的 | 估参数、定错误类型分布、校准 CRF、暴露流程问题 | 提供效能与增量的正式估计 |
| 金标准 | 同样执行双人盲法 + 仲裁（可只对子集做） | 全集合执行 |
| LLM | 只在**语义错误富集子集**上跑 | 在富集子队列上跑 |
| 产出 | 参数估值、流程 SOP、CRF 定稿 | 全部终点指标、论文/标书图表 |

## 3. 样本量估算

### 3.1 估算目标（三类，取最大值）

| 目标 | 参数 | 公式思路 |
|---|---|---|
| **T1 一致性精度** | 期望 kappa、精度（CI 半宽） | Fleiss 近似方差 |
| **T2 敏感度 CI 宽度** | 期望 Se、精度 d | 比例精度公式（Wilson/Agresti-Coull） |
| **T3 特异度 CI 宽度** | 期望 Sp、精度 d | 比例精度公式 |

### 3.2 公式

**比例精度（敏感度/特异度）：**

```
n = z²(1−α/2) · P(1−P) / d²
```

**kappa 精度（Fleiss 近似）：**

```
Var(κ̂) ≈ P_o(1−P_o) / [ n · (1−P_e)² ]

n = z²(1−α/2) · P_o(1−P_o) / [ d² · (1−P_e)² ]
```

其中 `P_o` 为观察一致率、`P_e` 为期望一致率、`κ = (P_o − P_e)/(1 − P_e)`。

> 更精确的做法是 Donner & Eliasziw 的 kappa 置信区间方法或**基于初勘参数的 bootstrap/蒙特卡洛模拟**。**需与统计确认**最终采用哪一种。

### 3.3 示例计算（**样例，非承诺，须据初勘调整**）

**示例 1 — kappa 精度（T1）**：设 `κ ≈ 0.7`、`P_e ≈ 0.5` → `P_o = 0.85`，`α = 0.05`（z = 1.96），精度 `d = ±0.10`：

```
n = 1.96² × 0.85 × 0.15 / (0.10² × (1−0.5)²)
  = 3.8416 × 0.1275 / (0.01 × 0.25)
  ≈ 196
```

→ **约 200 份报告**即可使 kappa≈0.7 的 95% CI 半宽约 ±0.10。

**示例 2 — 敏感度精度（T2）**：设 `Se ≈ 0.85`、`d = ±0.05`：

```
n = 3.8416 × 0.85 × 0.15 / 0.05² ≈ 196 份【含错报告】
```

**示例 3 — 特异度精度（T3）**：设 `Sp ≈ 0.90`、`d = ±0.05`：

```
n = 3.8416 × 0.90 × 0.10 / 0.05² ≈ 139 份【正常报告】
```

**综合示例区间**：

| 口径 | 示例样本量 | 说明 |
|---|---|---|
| 仅求一致性（kappa≈0.7，±0.10） | **约 200 份** | 最低门槛 |
| 同时求 Se/Sp（各 ±0.05） | 含错 ≈196 + 正常 ≈139 | 若含错率约 50%，合计约 **400 份** |
| 需分层（错误类型 × 部位） | 建议 **≥300–400 份** | 分层后每格样本量会显著变小 |

> ⚠️ **重要提醒**：
> 1. 以上为**示例**。真实数值依赖初勘得到的（a）错误率、含错率，（b）kappa 的 `P_e`，（c）各错误类型的占比。**须据初勘重算，并经统计确认。**
> 2. kappa 对**患病率（prevalence）高度敏感**。若错误率过低，kappa 会被人为压低（kappa paradox），应同时报告 **PABAK / Gwet's AC1** 作为稳健性指标。
> 3. 研究 B 的富集子队列所需样本量取决于"规则漏报率"；若规则漏报区很小，须通过**富集抽样 + 逆概率加权**保证有效样本量（见 §4.5、§6.4）。

## 4. 金标准与阅片流程

### 4.1 金标准建立方式

| 项 | 规定 |
|---|---|
| 阅片者 | **2 名资深放射科医师**（建议副高及以上、≥5 年报告经验；**具体年限需与放射科确认**） |
| 盲法 | 两人**相互独立、互不知晓对方结论**，且**均不知晓系统输出** |
| 仲裁 | 两人意见分歧时，由**第三人（高年资专家）仲裁**，仲裁结论为最终金标准；或采用**专家共识会议**（majority/consensus） |
| 输入一致性 | 每次阅片**只看报告文本 + 元数据**（与系统输入完全相同），**不看原始影像**、不看系统提示 |
| 记录内容 | 每份报告逐条记录：错误类型、位置（snippet/字符偏移）、严重度（high/medium/low）、是否影响诊断/安全 |
| 判读单元 | 报告级（有/无错误）与**错误条目级**（每条错误为一个单元）双层记录 |

> **金标准的主观性**是本研究最大的内部威胁之一（§9.3）。缓解手段：明确《金标准判读手册》、统一错误类型定义（直接对齐 `docs/LLM质控数据标注范式.md` 的 taxonomoy）、预试校准（pilot 阶段培训与一致性检验）。

### 4.3 阅片界面与记录表（CRF）字段

**CRF 字段（每份报告一行 + 每条错误一行）：**

| 层级 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 报告级 | `report_id` | 字符串 | 脱敏编号，不含住院号/姓名 |
| 报告级 | `modality` / `body_site` / `report_type` | 枚举 | 模态/部位/报告类型 |
| 报告级 | `source` | 枚举 | 人工录入 / OCR / PACS 推送 |
| 报告级 | `ocr_quality` | 枚举 | 不适用 / 良 / 中 / 差（OCR 来源必填） |
| 报告级 | `has_error` | 布尔 | 报告级是否有错误 |
| 错误级 | `error_seq` | 整数 | 第几条错误 |
| 错误级 | `error_type` | 枚举 | 对齐 R1–R25 分类 |
| 错误级 | `snippet` | 字符串 | 原文精确子串 |
| 错误级 | `span` | [int,int] | 字符偏移 |
| 错误级 | `severity` | 枚举 | high/medium/low |
| 错误级 | `clinical_impact` | 枚举 | 无/轻微/可能影响诊断/可能影响安全 |
| 错误级 | `rater_id` | 字符串 | 阅片者编号（R1/R2/仲裁） |
| 错误级 | `note` | 文本 | 备注 |

> 建议直接用 `docs/LLM质控数据标注范式.md` 的 JSON schema 落盘，便于与系统输出直接对齐比对。

### 4.4 防止阅片者被系统提示污染

**核心原则：先人工判读、后系统运行**，两者物理/时间上分离。

| 措施 | 做法 |
|---|---|
| 顺序约束 | 人工金标准**全部完成并锁定**后，才运行系统；系统输出不回流给已阅片的医师 |
| 时间洗脱 | 若必须交叉，设置 **≥2 周洗脱期**，并采用**随机交叉设计**（一半报告先人工后系统，一半反之） |
| 界面隔离 | 阅片界面**不显示**系统结论、评分、提示；不显示"该报告已有系统告警" |
| 数据隔离 | 系统输出写入独立表/文件，阅片者账号无权读取 |
| 审计 | 记录阅片时间戳与系统运行时间戳，供事后核查污染 |

> **需与伦理委员会确认**：盲法设计与洗脱期安排是否满足要求。

### 4.5 研究 B 的抽样设计（与 A 分开）

研究 B 若在连续队列上直接跑，会因"规则漏报区太小"导致 Δrecall 估计不稳。故采用**嵌套富集 + 逆概率加权**：

| 步骤 | 做法 |
|---|---|
| 1 | 在研究 A 的全队列上先跑**规则引擎**，得到"规则检出错"与"规则未检出错"两个集合 |
| 2 | 金标准确认为真错误、且规则未报的 → **规则漏报区**（研究 B 的目标总体） |
| 3 | 对"规则漏报区"**全部纳入**；同时按错误类型**分层随机抽样**补充语义类错误报告，形成富集子队列 |
| 4 | 在富集子队列上跑**规则+LLM**，比较其相对"仅规则"的增删 |
| 5 | 分析时对富集部分施加**逆概率权重**（1/抽样概率），回推至连续队列的总体 |

> 富集抽样会改变样本的错误率分布，**必须加权**才能得到总体无偏估计；未加权的结果只能作为"语义子群"的描述，**须与统计确认**加权口径。

## 5. 结局指标

### 5.1 研究 A：规则引擎（全队列）

| 指标 | 定义 | 层级 |
|---|---|---|
| 敏感度 Se（分层） | 金标准判为错误、系统亦报出 / 金标准判为错误 | 报告级 + 错误条目级，按错误类型分层 |
| 特异度 Sp | 金标准判为正常、系统亦未报 / 金标准判为正常 | 报告级 + 错误条目级 |
| PPV / NPV | 分别按阳性/阴性预测值定义 | 报告级 + 分层 |
| recall / precision | 错误条目级的检出率 / 报出条目中真错误占比 | 错误条目级，总体与分层 |
| 一致性 | Cohen's kappa（两阅片者；系统 vs 金标准）；>2 阅片者用 Fleiss' kappa | 报告级 |
| 稳健一致性 | PABAK、Gwet's AC1 | 报告级（应对患病率偏倚） |
| 漏报分布 | 假阴性按错误类型/部位的分布 | 描述性 |
| 误报分布 | 假阳性按错误类型/部位的分布 | 描述性 |

### 5.2 研究 B：LLM 语义层（规则漏报区）

| 指标 | 定义 | 说明 |
|---|---|---|
| **增量召回率 Δrecall** | LLM 在规则漏报区新检出、且金标准确认为真错误的条目数 ÷ 规则漏报区金标准真错误总条目数 | **主终点** |
| **新增误报率 ΔFP** | LLM 新报出、但金标准判为无该错误的条目数 ÷ LLM 在漏报区新报出的条目总数 | 与 Δrecall 成对报告 |
| 净增量 | Δrecall 与 ΔFP 的净收益（如每千份报告的净正确检出变化） | 决策视角 |
| 语义亚型分层 | 随访建议缺失 / 良恶性与处置建议不匹配 / 叙事规范 等分别报告 Δrecall、ΔFP | 对应 §4.2 语义类规则 |

### 5.3 效率与人因指标

| 指标 | 定义 | 采集方式 |
|---|---|---|
| 人工耗时 | 每份报告人工质控/审阅耗时（分钟） | 阅片计时（CRF 记录起止时间戳） |
| 系统耗时 | 规则链耗时（毫秒级）与 LLM 链耗时（秒级） | 系统日志 |
| 相对效率 | 人工耗时 ÷ 系统耗时 | 计算 |
| **采纳率（读片者干预）** | 系统提示被医师采纳（修改报告）的比例 | 需要**前瞻性前端埋点或回顾性复盘**：统计"系统报警→报告被修改"的转化率；**须与工程/临床确认可行口径** |
| 误报负担 | 每份报告平均误报条数（医师需排除的噪声量） | 系统输出 + 金标准 |

> **采纳率**是"系统提示对医师行为影响"的指标，与"系统是否正确"是两件事，须分开解读。回顾性数据可能无法可靠获得采纳率，若无法获得，须在局限中明确声明。

| 部位 | 胸部 / 腹部 / 头颅 / 脊柱 / 乳腺 / 其他 |

## 6. 统计分析

### 6.1 分析集

| 分析集 | 定义 | 用途 |
|---|---|---|
| 全分析集（FAS） | 所有符合入排标准且有金标准判读的报告 | 研究 A 主分析 |
| 可评价集（PPS） | 排除"金标准不可判定"的报告 | 敏感性分析 |
| 富集加权集 | 研究 B 的富集子队列 + 逆概率权重 | 研究 B 主分析 |

### 6.2 一致性分析

| 场景 | 方法 |
|---|---|
| 两名阅片者之间 | Cohen's kappa（+ 95% CI） |
| 系统 vs 金标准 | Cohen's kappa |
| >2 名阅片者 | Fleiss' kappa |
| 患病率偏倚 | 同时报告 PABAK、Gwet's AC1 |
| 一致性强度解读 | Landis & Koch：<0 差；0–0.20 轻微；0.21–0.40 一般；0.41–0.60 中等；0.61–0.80 较好；0.81–1.00 极好 |

### 6.3 置信区间方法

| 参数 | 推荐方法 | 备选 |
|---|---|---|
| 敏感度/特异度/PPV/NPV | **Wilson score 区间** | Clopper-Pearson 精确法 |
| kappa | **Bootstrap（如 2000 次，BCa）** | Fleiss 近似、Donner-Eliasziw |
| 配对差异（系统 vs 人工；规则 vs 规则+LLM） | **Bootstrap 配对差异的 95% CI** | — |
| 小样本/极端比例（如 0/109） | 精确法 | — |

> 当检出数为 0（如某错误类型特异度 100%）时，wald 区间会塌缩，必须用**精确法或单侧规则**；**须与统计确认**统一口径。

### 6.4 分层比较与多重比较

| 项 | 规定 |
|---|---|
| 分层比较 | 各错误类型/部位的 Se、Sp 用森林图呈现；组间比较用卡方/Fisher 或 **McNemar 检验**（配对） |
| 配对检验 | 系统 vs 人工在同一批报告上为**配对数据** → 用 McNemar（报告级）、或条目级配对检验 |
| 增量检验 | 规则 vs 规则+LLM 为**配对** → McNemar / 配对 bootstrap |
| 多重比较 | **预设主终点**（研究 A：报告级 Se；研究 B：Δrecall）；分层/亚组分析为**探索性**，用 **Benjamini-Hochberg FDR** 控制假发现率，并明确报告"探索性、不用于确证" |
| 富集加权 | 研究 B 的富集子队列必须加权（逆概率），权重口径**须与统计确认** |

### 6.5 缺失与不可判定样本的处理规则

| 情况 | 处理规则 |
|---|---|
| 报告文本缺失/截断 | **排除**（入排标准已定义），报告排除数与理由（流程图） |
| 金标准判读缺失（阅片者退出等） | 不纳入 FAS；若缺失比例 >5%，做**敏感性分析**（多重填补或 worst-case） |
| 阅片者分歧且无仲裁 | 记为"不可判定"，从主分析排除，并单独报告其比例 |
| OCR 质量差导致不可判读 | 若纳入则**单独分层**；主分析中可排除并做敏感性分析 |
| 系统运行失败（LLM 不可用/超时） | 按**非缺失**处理：记录为"未报出"，同时在敏感性分析中排除；须报告失败率（这也是效能的一部分） |
| 同一报告多条错误 | 条目级分析用**广义估计方程（GEE）**或聚类 bootstrap 处理报告内相关性 |

## 9. 风险与局限

| # | 风险/局限 | 影响 | 缓解措施 |
|---|---|---|---|
| 9.1 | **单中心** | 外部推广性受限；报告书写习惯单一 | 明确声明；后续多中心扩展；详细报告机构特征 |
| 9.2 | **回顾性** | 无法完全排除选择偏倚；采纳率难以可靠获得 | **连续入组**；预注册分析计划；采纳率无法获得时明确声明 |
| 9.3 | **金标准主观性** | 错误界定因人而异，可能高估/低估 Se/Sp | 双人盲法 + 第三人仲裁；判读手册；pilot 校准一致性；报告阅片者间 kappa |
| 9.4 | **OCR 质量** | 字符错乱同时污染系统与金标准 | OCR 来源单独分层；设定质量门槛；敏感性分析 |
| 9.5 | **系统版本漂移** | 中途改规则/换模型使结果不可复现 | **冻结版本**：记录 `version.py` 版本号 + git commit + 规则配置哈希 + LLM 模型/LoRA 版本 + `prompt_mode`；研究期内不改代码；变更即重启研究或做敏感性分析 |
| 9.6 | **报告类型偏倚** | 只纳入常见类型，结果不覆盖全部检查 | 预设报告类型清单；按类型分层报告；声明适用范围 |
| 9.7 | **LLM 配置不可用** | `full` 模式对每份报告都报错（特异性 0%），若误用会全面污染结果 | **锁定 `prompt_mode=ft`**；运行前做 20 例健全性检查；记录配置哈希 |
| 9.8 | **零事件/患病率偏倚** | 某些错误类型样本极少 → CI 极宽或 kappa 悖论 | 报告精确区间；同时报 PABAK/AC1；合并稀有类型或仅描述 |
| 9.9 | **报告内错误相关** | 同一报告多条错误不独立 | GEE / 聚类 bootstrap |
| 9.10 | **数据合规边界** | 未注册、未等保；表述不当有合规风险 | §7.3 声明；对外材料经法务/医务审核 |
