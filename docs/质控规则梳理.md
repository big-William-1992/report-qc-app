# 星衍 AI 放射质控系统 · 质控规则系统梳理

> **依据**：项目 `README.md` 第四、五章（规则引擎详解 / 评分说明） + `src/engine.py` 规则引擎实现。
> 代码（`engine.py`）为规则的最终权威定义；本文档是对它的系统化、可维护版梳理。
> **版本快照**：APP_VERSION 4.3。引擎启用 **R1–R12、R14、R15、R17、R18**；**R13 预留**（无对应规则）；**R16 可选**（随访时限，默认关）。

---

## 一、引擎管线

```
报告文本 → 分段(NER 段落划分) → 中文临床 NER(实体/侧别/性别/阳性征)
       → 解剖知识图谱约束(RadLex 器官族 + 左右侧比对表)
       → 规则引擎(R1–R18) → 错误明细(Finding) + 四维评分
```

- **NER**：`ChineseRadiologyNER` 将正文划分为 `findings`(检查所见/影像描述)、`impression`(诊断印象/结论)、`meta`(患者信息) 三段；抽取男女专属器官、带左右前缀的解剖实体、阳性征等。
- **知识图谱（`_KG`）**：性别专属器官（`GENDER_ORGANS`）、部位归一化（`SITE_NORM`）、模态→评分标准（`MODALITY_SCORE`）、左右侧比对表。
- **降级**：中文 NLP 包（`zh_radiology_synonyms` / `zh_ner`）以 `try/except` 懒加载，缺失时不影响既有规则（仅 R16 依赖 NLP，缺则跳过）。

## 二、四维评分体系

**严重度权重**：`high = −30` / `medium = −15` / `low = −5`。

| 维度 | 计算方式 | 触发扣分的规则 | 下限 |
|---|---|---|---|
| **准确性** | `100 − Σ(各发现严重度权重)` | **全部规则的错误都计入**（聚合扣分池） | 0 |
| **完整性** | 命中 R3 → `80`，否则 `100` | R3（评分标准缺失）专属 | 80 |
| **规范性** | 存在任一质控问题 → `90`，否则 `100` | 二值，不细分具体规则 | 90 |
| **及时性** | 固定 `100` | 预留维度，当前无规则 | 100 |

> ⚠️ **重要解读**：当前评分是**聚合式**，并非"每条规则归属某一维度"。
> 即——所有规则的发现都进**准确性**扣分池；**完整性**只由 R3 决定；**规范性**只是"有无问题"的二值开关。
> 看板上的"准确性低"代表"发现的问题多/严重"，不等同于"只有 R1/R2 这类矛盾规则"。

分数结构（`engine.score()`）返回每维度 `{score, deductions:[{rule, delta, reason}]}`，前端"评分依据区"逐项展示扣分的规则号与原因（黑盒变透明）。

## 三、规则全集（按编号）

### R1 性别矛盾 ｜ 严重度：高 ｜ 类型：矛盾类
- **输入**：`meta.gender`（优先）→ 正文推断；正文男女专属器官实体（`gender_organ`）
- **判定**：报告性别与文中男女专属器官（前列腺/子宫/卵巢/睾丸…）冲突即报
- **边界**：性别无法确定（无 meta 且正文无可解析）→ **不判**，避免臆断
- **自动修正**：否 ｜ **可配置**：否（器官词典见 `GENDER_ORGANS`）

### R2 左右侧混淆 ｜ 严重度：高 ｜ 类型：矛盾类
- **输入**：带左右前缀的解剖实体（`L-kidney`/`R-kidney`），按器官族归组
- **判定**：同一解剖部位族在 `findings` 与 `impression` 段方位（左/右）互斥即报
- **边界**：仅在描述段与印象段之间比较；含肺跨段（已修复漏报）
- **自动修正**：否 ｜ **可配置**：否

### R3 评分标准缺失 ｜ 严重度：中 ｜ 类型：缺失类（完整性）
- **输入**：`meta.modality` + 正文正则
- **判定**：乳腺/钼靶→要求 `BI-RADS`，前列腺/盆腔→要求 `PI-RADS`；报告未检出对应评分即报
- **边界**：无 modality 或未要求评分的模态 → 不判
- **自动修正**：否 ｜ **可配置**：否（映射见 `MODALITY_SCORE`）
- **评分影响**：命中时**完整性 = 80**

### R4 计量单位错误 ｜ 严重度：低 ｜ 类型：规范类
- **输入**：`bad_unit` 实体
- **判定**：检出非常规单位（非 cm/mm/HU/ml/° 等）即报
- **自动修正**：否 ｜ **可配置**：否

### R5 描述-结论矛盾 ｜ 严重度：中 ｜ 类型：矛盾类
- **输入**：按规范器官族归组；描述段某器官族出现阳性征（`POSITIVE_MARKERS`）+ 印象段是否提及该器官族并给结论
- **判定**：描述段器官提示阳性征，但印象段未就该器官给出对应结论即报
- **自动修正**：否 ｜ **可配置**：否

### R6 登记部位不符 ｜ 严重度：高 ｜ 类型：矛盾类
- **输入**：`meta.applied_site`（申请部位，归一化）+ 报告正文涉及的解剖部位族
- **判定**：申请部位归一化后不在报告正文涉及的部位族集合中即报（"申请胸部却写腹部"）
- **边界**：仅扫描正文（检查所见+印象），排除元信息头部，避免"申请部位"自身被计入
- **自动修正**：否 ｜ **可配置**：否
- **与 R18 关系**：R6 抓"部位错配"，R18 抓"区域器官漏写"，互补

### R7 描述内部矛盾 ｜ 严重度：中 ｜ 类型：矛盾类
- **输入**：同一 `findings` 段内的 `gender_organ` 实体
- **判定**：描述段内同时出现男女专属器官（不可能同时为真）即报
- **自动修正**：否 ｜ **可配置**：否

### R8 同音错别字 ｜ 严重度：中 ｜ 类型：规范类（唯一可自动修正）
- **输入**：正文 + `rules_config.typos`（错词→正确词）
- **判定**：命中错别字词典即报（如"姐姐→结节""占为→占位"）
- **去重**：按错词长度降序匹配，优先命中更长错写，跳过已被覆盖区间
- **自动修正**：**是**（仅 R8 可安全替换，逐条预览确认）｜ **可配置**：**是**（GUI 增删，持久化到 `rules_config.json`）

### R9 自定义互斥冲突 ｜ 严重度：中（可配） ｜ 类型：规范类
- **输入**：`rules_config.conflicts`（词 A / 词 B / 范围 / 严重度 / 备注）
- **判定**：同一范围内 A 与 B 同时出现即报（如"增强"与"平扫"不应共存）
- **范围**：`正文`（默认，整篇）/ `描述段`（仅影像描述）
- **可配置**：**是**（GUI 维护）

### R10 模板合规 ｜ 严重度：低（可配） ｜ 类型：缺失类
- **输入**：`rules_config.template`（默认 `required_sections=[findings,impression]`, `require_followup=true`）
- **判定**：缺"检查所见"段 / 缺"诊断印象/结论"段 / 未给随访建议，分别告警
- **可配置**：**是**（改 `required_sections` / `require_followup` / `severity`）

### R11 信息框-正文矛盾 ｜ 严重度：高/中 ｜ 类型：矛盾类
子规则：
- **R11-GENDER**：`meta.gender` 与正文解析性别矛盾
- **R11-SIDE**：信息框侧别（项目/检查部位/申请部位兜底）与描述段或结论段仅提对侧矛盾
- **自动修正**：否 ｜ **可配置**：否
> 注：原 `R11-ABNORMAL`（描述阳性、结论称正常）已并入 **`R17-NORMALITY`**（见 R17 说明）。

### R12 句子前后文 ｜ 严重度：中 ｜ 类型：矛盾类
子规则（单句内）：
- 同一句话内男女专属器官混用
- 同一句话内既称"未见异常"又描述阳性征（须 region-specific 正常，避免"余两肺未见异常"误报）
- **自动修正**：否 ｜ **可配置**：否

### R14 前后文（跨段） ｜ 严重度：中/高 ｜ 类型：矛盾类
子规则（检查所见 ↔ 诊断印象）：
- **R14-NATURE**：良恶性定性矛盾（描述 vs 结论方向相反）
- **R14-COUNT**：病灶数量前后不一致
- **R14-SIDE**：同器官左右跨段矛盾（覆盖文本级 + 英文报告 MIMIC/IU-Xray 风格）
- **自动修正**：否 ｜ **可配置**：否
> 注：原 `R14-NORMAL`（描述正常、结论异常）已并入 **`R17-NORMALITY`**。

### R15 上下文（段内） ｜ 严重度：中/高 ｜ 类型：矛盾类
子规则（同描述段内跨句）：
- **R15-NORMAL**：段首称未见异常但段内描述阳性征
- **R15-SIDE**：同器官在描述段内前后左右矛盾
- **R15-PRESENCE**：同一病灶先描述存在、后又称未见/消失
- **自动修正**：否 ｜ **可配置**：否

### R17 逐部位精确比对 + 正常性矛盾 ｜ 严重度：高 ｜ 类型：矛盾类（精确）
- **输入**：描述段与结论段按 `(器官, 侧别)` 精确到同一部位的 正常/异常 声明
- **判定**：同一部位"描述正常、结论异常"或"描述异常、结论正常"即报矛盾
- **精细化**：可区分左右侧、精准定位矛盾部位（左小脑正常+右小脑软化灶→不误报；左小脑正常+左小脑软化灶→报矛盾）
- **段级兜底**：无法归属具体部位时回退段级语义，避免漏检
- **统一 rule_id `R17-NORMALITY`**：所有"描述↔结论正常性矛盾"——逐部位（描述正常/异常↔结论异常/正常）与段级兜底（原 `R11-ABNORMAL` 描述阳性结论正常、`R14-NORMAL` 描述正常结论异常）——现已合并为单一 `rule_id`，保留各自 `error_type`/message 的多粒度判定。前端按 `R17-NORMALITY` 聚合展示，不再出现"多条描述正常结论异常"类重复告警。
- **自动修正**：否 ｜ **可配置**：否

### R18 检查部位器官漏写 ｜ 严重度：中 ｜ 类型：缺失类（完整性/区域覆盖）
- **输入**：`meta.applied_site`（支持"胸部、上腹部"多区域拆分）+ 描述段
- **判定**：登记某区域但描述段未命中该区域任一器官（如"登记上腹部"却只写肺）即报漏写
- **防误报**：① 整段"未见异常"整体声明不误报；② 只查描述段；③ 多区域分别校验互不牵连；④ 仅校验"区域至少描述一器官"，不逐器官核对
- **自动修正**：否 ｜ **可配置**：否
- **与 R6 关系**：互补（R6 部位错配 / R18 区域器官漏写）

### R16 随访时限缺失 ｜ 严重度：低 ｜ 类型：缺失类（可选，默认关）
- **输入**：中文 NER 随访抽取（`_zh_extract_followup`）
- **判定**：给出随访/复查建议但未明确时限（如"3个月后"）即报
- **默认关闭**：避免对常规"定期复查"过度告警；需真实样本验证后再开启（`enable_r16=true`）
- **可配置**：**是**（开关）

### R13 预留编号
- 当前无对应规则，引擎不调用 `_r13_*`。保留编号以便后续扩展，不影响现有逻辑。

## 四、规则按错误类型归类

| 类别 | 规则 | 主要维度 |
|---|---|---|
| **矛盾/一致性类**（逻辑自洽） | R1, R2, R5, R6, R7, R11, R12, R14, R15, R17 | 准确性（聚合扣分） |

## 五、可配置规则（rules_config.json）

**位置**：
- 打包后：`%APPDATA%/MedicalReportQC/rules_config.json`（首次运行从 exe 同级 `assets/` 复制初始文件，避免装到 Program Files 后只读）
- 开发态：`assets/rules_config.json`

**结构**：
```json
{
  "typos": { "姐姐": "结节", "占为": "占位" },        // 驱动 R8，GUI 可增删
  "conflicts": [                                     // 驱动 R9
    { "a": "增强", "b": "平扫", "scope": "正文",
      "severity": "medium", "note": "增强与平扫不应共存" }
  ],
  "template": {                                      // 驱动 R10
    "required_sections": ["findings", "impression"],
    "require_followup": true,
    "severity": "low",
    "note": "结构化报告建议含检查所见与诊断印象/结论段，并给出随访建议"
  },
  "enable_r16": false,                               // 驱动 R16（默认关）
  "ignores": []                                      // 忽略词（预留）
}
```
- 加载失败（文件缺失/JSON 错误）→ **回退内置默认值**，保证引擎始终可用。
- 修改即时生效（GUI 保存即写盘，下次运行自动重载）。

**GUI 维护入口**（README 第六章）：⚙ 规则维护弹窗两个页签——「错别字词典」「互斥冲突」，修改持久化到上述 JSON。

## 六、规则与 NLP 对应关系（NER / 知识图谱依赖）

### 6.1 结论
当前质控规则 **有对应 NLP**，且是其核心支撑；但不是 GPT / 大模型类神经 NLP，而是**词典/规则式中文 NLP + 解剖知识图谱**（命名实体识别 NER + RadLex 知识图谱归一）。优点：完全离线、零第三方依赖、可单测、易打包；已预留模型后端接口，未来可零改动切换。

### 6.2 NLP 在管线中的位置
报告文本 → 按「影像描述/印象/患者信息」**分段** → **中文 NER 实体抽取**（部位/侧别/征象/程度/随访）→ **解剖知识图谱归一 + 左右侧别建模** → 规则引擎 R1–R18 → 错误明细 + 四维评分。

### 6.3 支撑模块（均已确认在 `src/` 且打进 exe）

| 模块 | 类型 | 在引擎里的角色 | 依赖性质 |
|---|---|---|---|
| `anatomy_lexicon.py` | 解剖知识图谱（RadLex 器官族 + PadChest 104 部位→UMLS，中文同名归一 + 侧别建模）| 部位归一化、左右侧比对的底座；R2/R5/R6/R14/R17/R18 全靠它 | **硬依赖**（engine 顶层直接 `from anatomy_lexicon import`，无 try/except）|
| `zh_ner.py` | 中文临床 NER（词典式，抽 部位/征象/程度/随访）| 补充 sign/followup/degree 实体；驱动 R16 随访时限 | **软依赖**（try/except 保护，`_ZH_NLP_OK`；缺则降级）|
| `zh_radiology_synonyms.py` | 中文征象同义词归一 | 喂给 zh_ner | 随 zh_ner（软依赖）|
| `engine.py` 内建 `ChineseRadiologyNER` | 词典式 部位/侧别/measurement 抽取 | 即使 zh_ner 缺失，核心结构规则仍靠它工作 | 自带同义词表，不依赖 zh_ner |

> **发布版是否带 NLP**：打包 spec 的 `datas` 把整个 `src/` 平铺进 exe；运行时 `desktop_app` 把 `src/` 加进 `sys.path` → 可正常 import。因此 `latest` exe **自带 NLP**（此前 sqlalchemy 缺失崩在更前、未触达 NLP 层，该问题已修于 `d1d787d`）。

### 6.4 逐规则 NLP 依赖矩阵

**强依赖 NLP / 知识图谱（需"理解"部位与左右侧才判得出来）：**

| 规则 | 依赖的 NLP 能力 |
|---|---|
| R2 左右侧混淆 | NER 抽带 `L-/R-` 前缀解剖实体，按器官族归组比描述段 vs 印象段 |
| R5 描述↔印象一致性 | NER 实体 + 段落划分 |
| R6 登记部位不符 | 申请部位 vs 报告主体解剖，知识图谱归一化比对 |
| R14 前后文（跨段） | NER + 跨段兜底表（anatomy_lexicon 派生）|
| R16 随访时限缺失 | **纯 NLP 驱动**（zh_ner 抽 followup 实体），缺 zh_ner 则跳过（默认还关）|
| R17 逐部位精确比对 | anatomy_lexicon 部位词表 + 侧别 |
| R18 区域器官漏写 | anatomy_lexicon 区域→器官映射 |

**不依赖外部 NLP 软包（纯正则 / 词典 / 阈值 / meta 比对，或仅用引擎内建实体）：**
R1（meta 比）、R3/R4（模板/单位正则）、R7（内建 `gender_organ` 实体）、R8/R9（错别字/互斥词典，rules_config 驱动）、R10（模板校验）、R11/R12/R15（段级/句级矛盾，基于内建实体）、R13（预留）。

> 注：R7/R11/R12/R15 用引擎内建 `ChineseRadiologyNER` 抽 `gender_organ` 等实体，属轻量 NLP，但**不依赖**外部 zh_ner 软包；真正依赖 zh_ner 软包的只有 **R16**。

### 6.5 模型切换预留
代码已预留切换接口：`NERBackend` 抽象基类（定义 `extract(text) -> List[Entity]`）+ `LexiconBackend`（当前默认）+ 未来 `ModelBackend`（等 CBLUE/CCKS 训练或接 CMedKG 图谱推理后，实现 `ModelBackend.extract` 并经 `set_backend()` 切换，引擎其余代码不变）。

### 6.6 如何验证发布版 NLP 已生效
用一条含"左肾结石、右肾囊肿"但印象只写"右肾结石"的报告跑质控：
- 能报 **R2 左右矛盾** → 说明 NER + 解剖知识图谱正在工作；
- 未报 → 检查 exe 同级 `src/anatomy_lexicon.py` 是否随包释出，或 `crash.log` 是否提示 NLP 加载异常（软包缺失只会让 R16 失效，不影响 R2）。

## 七、设计原则与安全边界

1. **仅 R8 可自动修正**：错别字是确定映射，可安全替换并逐条预览确认。**矛盾类**（性别/左右/描述-结论）、**缺失类**、**规范类**一律只提示人工确认，**绝不自动改写**，避免同音误判（如"简易→建议"用对时）污染正式报告。
2. **否定语境防误报**：阳性征匹配对"未见 / 未见明显 / 无 / 不伴"等前缀后的词不计入异常（`_NEG_PREFIXES`），如"未见明显炎症""无增生"不会误判为阳性。
3. **部分正常不误报**：R11/R14/R15/R17 用严格"整段无阳性才算正常 / 整段无正常才算异常"语义，避免"右肺上叶见结节、余两肺未见异常"这类标准报告被误判。
4. **逐部位精确比对（R17）**：可区分左右侧、精准定位矛盾部位，避免跨侧误报。
5. **区域覆盖防误报（R18）**：整段"未见异常"整体声明不误报；多区域分别校验互不牵连。
6. **降级容错**：中文 NLP 缺失不影响既有规则；配置加载失败回退默认。
