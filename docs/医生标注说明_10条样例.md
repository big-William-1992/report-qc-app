# 医生标注说明（一页纸 · 约 30–60 分钟/10 条）

> 目的：用**您的专业判定**给 10 份脱敏放射报告"判卷"，用来衡量我们系统的检出能力。
> 您只需要判断"**这份报告有没有质控意义上的错误**"，**不需要修改报告**。

---

## 一、您要做的三件事（每条报告）

打开 `data/semantic_eval/candidates_sample10.jsonl`（可用文本编辑器或 Excel/表格工具）。
每条记录里，只填 `label` 里的 5 个字段 + 把 `label_source` 改成 `human`：

| 字段 | 怎么填 | 是否必填 |
|---|---|---|
| `label_source` | 改成 `"human"`（表示人工判定，不是系统自产） | ✅ 必填 |
| `label.is_true_error` | `true`＝这份报告**存在**质控意义上的错误；`false`＝**没有**错误 | ✅ 必填 |
| `label.error_type` | 错误类型（见第二节表）。判为 `false` 时留空 | 判 true 时必填 |
| `label.location` | **错误所在的原句片段**（照抄报告里的几个字，便于定位） | 判 true 时必填 |
| `label.severity` | `high` / `medium` / `low`（您认为的严重程度） | 判 true 时必填 |
| `label.note` | 一句话说明理由。**若您觉得"规则/系统很难发现"，请特别写出来** | 建议填 |

**不要填**：`engine_snapshot_at_creation`（那是系统当时的判定，留作对照，别改）、`id`、`report_text`。

---

## 二、错误类型怎么选（两栏）

**A. 硬错误（写错了、前后矛盾——系统应该能查出来）**

| 类型 | 含义 | 例 |
|---|---|---|
| `R1-GENDER` | 性别与器官矛盾 | 女性报告出现"前列腺" |
| `R2-LATERALITY` | 左右矛盾 | 描述"右肺"、结论"左肺" |
| `R3-SCORE` | 应有评分却缺失 | 乳腺结节未给 BI-RADS |
| `R4-UNIT` | 单位/数值异常 | 结节"大小约 0.8m" |
| `R5-CONSISTENCY` | 描述与结论矛盾 | 描述"考虑恶性"、结论"未见异常" |
| `R6-SITE` | 登记部位与结论不符 | 登记"胸部"、结论写腹部器官 |
| `R8-TYPO` / `R19-HOMOPHONE` | 错别字 / 同音字 | "磨玻璃"写成"膜玻璃" |
| `R10-TEMPLATE` | 缺少必需段落 | 没有"诊断印象"段 |
| `R18-COVERAGE` | 阳性所见未在结论中体现 | 描述了结节，结论只字未提 |

**B. 语义错误（⚠️ 这一栏最重要——系统目前**最可能漏掉**这类）**

| 类型 | 含义 | 例 |
|---|---|---|
| `SEM-FOLLOWUP` | 该给随访/复查建议却没给 | 9mm 实性结节，通篇无随访建议 |
| `SEM-RECOMMEND` | 处置建议与所见不匹配 | "边缘毛刺"的 9mm 结节 → "无需特殊处理" |
| `SEM-CONCLUSION` | 结论倾向与描述不符 | 描述"考虑恶性可能"，结论"良性病变" |
| `SEM-NARRATIVE` | 叙事逻辑/规范问题 | 前文"双侧"，后文只写单侧；指代不清 |
| `OTHER` | 其它（请在 note 说明） | — |

> **请特别注意：**如果一份报告"读起来不太对，但又说不出违反了哪条硬规则"，
> 那大概率就是 **B 栏的语义错误** —— 这正是我们最想知道的部分。
> 如果 10 条里一条语义错误都没有，也请照实填（这本身是有价值的结论）。

---

## 三、判定的三个原则

1. **按"这份报告能否直接签发"来判**，不是按"文字是否优美"。
   措辞可以改进但内容无误的，填 `false`。
2. **不确定就不算错**（填 `false`，并在 `note` 写"存疑：……"）。
   宁可漏判，也不要把"可接受的写法"判成错误。
3. **单位是"一份报告"，不是"一句话"**：一份报告有多处错误时，
   填**最严重的那一处**的类型与定位，其余在 `note` 里补充。

## 四、填好的样子（示例）

```json
{
  "id": "sd-07",
  "part_hint": "腰椎",
  "report_text": "患者女，52岁。检查部位：腰椎。\n检查所见：腰椎生理曲度变直，L4/5椎间盘向后突出，硬膜囊受压。\n诊断印象：腰椎退行性变。",
  "label_source": "human",
  "label": {
    "is_true_error": true,
    "error_type": "R18-COVERAGE",
    "location": "L4/5椎间盘向后突出，硬膜囊受压",
    "severity": "medium",
    "note": "描述明确有椎间盘突出并压迫硬膜囊，结论只写'退行性变'，阳性所见未在结论体现"
  }
}
```

（上例是**演示格式**，不是标准答案——请按您的判断填。）

## 五、填完之后

1. 保存文件（JSONL：一行一条记录，不要加逗号、不要换行到多条）。
2. 交回后我会跑两个校验：
   - **格式校验**：字段是否完整（不合格会提示到具体行号）
   - **打分**：给出系统在这 10 条上的
     **检出率（敏感度）**、**误报率（特异度）**，并按错误类型分层
3. 结果的用途：判断"规则引擎够不够用"、"语义层（AI 那部分）要不要保留"。
   **这是目前唯一能回答这两个问题的数据。**

## 六、关于隐私

- 这 10 份报告来自**公开/合成语料**（`data/cpt_reports.jsonl`），不含真实患者姓名、
  住院号等标识信息；报告正文本身请勿外传，仅在院内使用。
- 若您希望用**真实院内报告**做更大规模（100–300 条）的评测，请先确认科室与院内数据合规要求；
  我们可以在脱敏后生成同样的模板。
