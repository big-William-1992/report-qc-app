## 1. 定位与付费方：谁真正付钱，钱从哪个科目出

定价的第一步不是算成本，而是**确认付款人、决策链与预算科目**。医院软件的成交价，本质由"谁的需求 vs 谁的钱"这对关系决定。

### 1.1 决策链角色表（按放射质控类软件的常见分工）

| 角色 | 在采购中的位置 | 关心什么 | 对定价的含义 |
|------|---------------|---------|-------------|
| **放射科**（主任 / 质控专员 / 技师） | **需求发起方 + 主要使用者 + 技术否定权** | 省事、别增加工作量、报告少返工、科室质控有记录 | 决定"能不能进去"。他们点头，才有后续 |
| **医务科 / 质控科** | **价值放大器 + 立项推动者** | 全院质控台账、可举证、迎检/等级评审材料、责任可追溯 | 决定"能不能卖上价"。把工具变成"管理留痕"的正是他们 |
| **信息科** | **技术评估 + 商务把关 + 常见合同归口** | 安全准入、内网部署、数据不出院、不增加运维负担、是否有合规材料 | 决定"能不能签"、以什么主体签、走什么流程 |
| **设备科** | **通常不参与**纯软件采购 | 大型设备、耗材、维保 | 不要把精力放在设备科；软件多归信息科口径 |
| **院领导 / 分管副院长** | **签字与额度审批** | 是否"上面要求"、是否有预算、风险谁担 | 需要一句话价值 + 一份可签的合同与发票主体 |
| **财务 / 采购办** | **流程执行** | 预算科目、限额、招标方式、发票类型、账期 | 决定报价单形式与付款节点，决定"几十块的单子没法走流程"（见 §2） |

**一句话结论**：**需求在放射科，钱的合法性来自医务科/质控科，流程开关在信息科，签字在院领导。** 报价单要同时服务这四类人：给放射科看"省多少事"，给医务科看"台账与迎检"，给信息科看"安全与合规材料"，给领导看"总价与周期"。

### 1.2 预算科目对照表

医院不会凭空造一个科目买软件。**报价前必须问清"这笔钱从哪来"**，它直接决定金额上限与采购方式。

| 预算科目 | 通常归口 | 金额量级（相对） | 采购方式倾向 | 对本产品的适配度 |
|---------|---------|----------------|-------------|----------------|
| **信息化建设经费 / 软件购置费** | 信息科 | 中–高 | 年度预算 + 招标 / 询价 / 竞争性磋商 | 主战场。**但要求资质材料最全**（软著、检测报告、等保配套等），见 §6 |
| **质控专项经费** | 医务科 / 质控科 | 中 | 专项立项 + 议价 | **最适配**。买的是"台账 + 留痕 + 可举证"，与产品能力天然对齐 |
| **等级评审 / 复审专项** | 医务科 + 院办 | 中–高，**时间敏感** | 专项 + 加急采购 | **最高付费意愿窗口**。评审有明确时间点，客户愿为"按期可用"付溢价（含实施加急费） |
| **科研课题经费** | 放射科 / 课题组 | 小–中，但**决策最快** | 课题内小额采购，常不需公开招标 | **最佳切入口**。可绕过大部分资质门槛，用于落第一单与出案例 |
| **科室业务费 / 科主任可支配经费** | 放射科 | 小 | 小额、快 | 适合单机版/小规模试用转正 |
| **基建/设备类经费** | 设备科 | — | — | 不适配，不要硬塞 |

**操作建议**：
- 报价单准备 **两版价格口径**（"科研/质量管理用途"版 与 "信息科立项"版），同一产品、不同交付与材料范围，金额不同。
- 首单优先走 **科研经费** 或 **质控专项**，把资质门槛绕过去；等有案例与用户报告后，再打信息化经费的正规流程（§7）。

### 1.3 两种价值主张的付费意愿差异（这是整个定价的核心杠杆）

同一个软件，讲成两种故事，能卖出的价格差一个数量级。**这不是话术问题，这是"客户把它记到哪个心理账户"的问题。**

| 维度 | 主张 A：「查错字 / 查矛盾的智能工具」 | 主张 B：「质控台账 + 等级评审与迎检支撑」 |
|------|-----------------------------------|--------------------------------------|
| 客户的心理对照物 | Word 拼写检查、免费在线工具、输入法纠错 | 人工质控投入的人力工时、纸质质控记录、迎检前临时补材料 |
| 使用频率 | 医生个人、随手用 | 科室/全院常规管理动作、按月/按季出报表 |
| 谁在听 | 医生个人 | **医务科 / 质控科 / 科主任 / 评审办** |
| 责任归属 | "你帮我看看" | "质控记录要留痕、要可追溯、检查时要拿得出来" |
| 付费主体 | 个人自费或科室零星支出 | 医院（法人）走预算科目 |
| 心理价位锚点 | **几十到几百元/年** | **万元级/年**（具体见 §4，**【需市场验证】**） |
| 可替代性 | 极高（免费工具一抓一把） | 较低（要留痕、要报表、要院内规则，替代成本高） |
| 议价空间 | 几乎没有 | 有，但可用"服务与周期性交付"支撑 |
| 生命周期 | 用完即走，续费意愿低 | 绑定科室管理流程，续费意愿高 |

**结论三条**：
1. **可以拿"查错字"做演示和引流，绝不能用它做报价口径。** 一旦客户把你归类为工具 A，后面所有价格都谈不上去。
2. **主力报价口径必须锚在"质控台账 + 过程留痕 + 可举证"。** 卖的是"科室质控这件事有人管、有记录、检查拿得出手"，不是"AI 帮你挑错字"。
3. **把"能生成给检查/评审看的材料"作为独立卖点单独标价**（§5 的"质控台账定制/迎检支持"），这是毛利最高、最容易被客户接受的部分。

> ⚠️ 表达边界：上述"台账/留痕/迎检支撑"只能讲**过程与记录**，**不得**讲成"能保证评审通过""能替代人工质控责任"。见 §8 红线。

## 2. 为什么 ¥59/年 是负信号

¥59/年 的来源可以理解（单机、个人、早期内测的心理定价），但它作为**面向医院**的报价，会传递错误信号并制造实际障碍。以下七条是机制性原因，不是"看不上便宜"的情绪判断。

### 2.1 七个具体机制

**① 价格锚定错误，且几乎不可逆。**
¥59 把产品锚进"消费级小软件/免费工具"的心理账户。价格锚一旦形成，后续把同一产品报到万元级，客户的第一反应是"去年还是 59，今年怎么五万"——**不是觉得新版本贵，而是怀疑你在宰他**。医院客户换供应商成本高、口碑传播快，一次"涨价被记恨"会污染整个区域市场。

**② 覆盖不了成本结构。**
医院软件的真实成本大头**不在开发，在交付**：环境适配、内网部署、RIS/PACS 接口联调、院内规范/词表定制、培训、以及常年售后响应。这些是**按"人·次/人·天"计的成本**，且必须由人（而小团队最缺人）。59 元/年连一次远程排障的人工都不够，更不用说上门。**用 59 元定价，等于承诺了一个团队无法交付的服务水平。**

**③ 采购流程成本 > 合同金额，客户内部会抵制。**
公立医院的采购/财务/验收/发票/资产入账都有一套固定流程，走完一套流程的**内部工作量是常数**。一份几十块的合同，信息科和财务要走的流程一模一样，收益却是零。结果不是"便宜好卖"，而是**没人愿意为你启动流程**。这是 HIT 销售里最常见的悖论。

**④ 供应商可信度被价格反推。**
医院采购者用价格推断风险：这么便宜 → 个人开发者？没有公司主体？能开票吗？明年还在吗？出了事找谁？**信息科的安全准入与领导签字，本质是在评估"风险由谁承担"**。过低价格会直接触发"不敢用"的结论，而不是"捡到便宜"。

**⑤ 招标与议价障碍。**
- 立项难：**预算做不出来**。医院年度预算是按金额编列的，59 元的条目无法立项，也无法说明"为什么需要这个专项"。
- 单一来源/竞争性谈判难：论证价格合理性时，缺乏可支撑的报价结构。
- 反而制造麻烦：金额过低可能落在某些"小额零星采购"规定之外，流程尴尬。
> 各地公开招标限额与采购方式差异较大，**【需市场验证】**，但"金额过小反而难走流程"这一方向性判断在多地上普遍成立。

**⑥ 售后预期被价格锁死。**
低价 = 客户对你"随时消失"的默认预期。于是客户**不敢把科室质控流程绑定进来**（万一下季度你不管了怎么办），产品就永远停在"试用看看"阶段，进不了核心业务，也就永远没有续费与扩展。

**⑦ 与合规投入的财务模型矛盾。**
项目已知约束是"未做二类器械注册、未做等保三级测评"。这两件事都是**六位数级别的投入**（具体金额**【需市场验证】**，注册周期现实区间为 12–24 个月，见 `docs/COMPLIANCE_GAP_ANALYSIS.md` §6.2）。59 元/年的商业模式在算术上不可能回收；用它做商业计划，会让整个资质投入显得没有意义。

### 2.2 成本结构速查（为什么必须是"结构"而不是"单价"）

| 成本类别 | 发生频率 | 是否随客户数线性增长 | 59 元/年能否覆盖 |
|---------|---------|-------------------|----------------|
| 研发与迭代 | 持续 | 部分 | 否 |
| 版本打包/签名/发版验证 | 每版本 | 否 | 否 |
| 首次部署与内网适配 | 每客户 | **是** | 否 |
| RIS/PACS 接口联调 | 每客户（若需要） | **是** | 否 |
| 培训（科室/管理员） | 每客户 | **是** | 否 |
| 规则/词表定制 | 每客户 | **是** | 否 |
| 常年售后与运维响应 | 持续，按客户数累积 | **是** | 否 |
| 合规资质（检测/等保/注册/律师） | 阶段性 | 否（摊销） | 否 |
| 商务（投标、合同、差旅、账期资金占用） | 每项目 | **是** | 否 |

**这张表说明**：定价必须**分离"软件授权"与"实施服务"**。把实施塞进 59 元里，等于用软件价格补贴服务，规模越大亏得越多——这正好解释为什么小团队"缺实施与售后人手"：**不是招不到人，是价格养不起人。**

### 2.3 替代结构（保留 ¥59 的正确用法）

不建议简单地把 ¥59 改成某个更大的数，而是**改变报价结构**：

| 动作 | 说明 |
|------|------|
| **把 ¥59 降级为"个人自费电子版"引流档** | 适用于医生个人、规培、科研自用，**明确不含任何实施与优先售后**，不签服务承诺，仅自助激活。用作口碑与试用转化，**不作为医院报价口径** |
| **另立"科室版 / 机构版"价目** | 见 §3、§4。医院场景一律从科室版起报，报价单上不出现 59 这个数字 |
| **实施与服务单列** | 见 §5。让客户看到"钱花在哪"，也让自己的服务有价 |
| **老客户价格过渡** | 已按 59 元付费的客户，给出"老用户保留价 + 免费升级到对应新档"的过渡政策，避免口碑反噬（这类客户数量少，成本可控） |
| **统一口径** | 同步更新 `TERMS_OF_SERVICE.md`、`PRD.md`、演示文案中的价格与版本描述，避免同一客户看到两种价格（口径不自洽是 `docs/COMPLIANCE_GAP_ANALYSIS.md` 已点名的风险类型） |

> ⚠️ 在完成 §8 的对外口径收敛**之前**，不要对外大范围宣传价格。**同一产品对外两种定位（非器械 vs 需注册）叠加两种价格，是商务风险的高发组合。**

## 3. 打包与分层建议（4 个版本）

设计原则：**按"使用边界"分层，而不是按"功能多少"砍**——因为医院买的是"够我科室用"，砍功能会砍掉成交可能。分层的作用是**给客户一个明确的选择锚，以及一条顺理成章的扩容路径**。

### 3.1 四档总览

| | **① 单机基础版** | **② 科室版**（主力） | **③ 机构版** | **④ 私有化 + 实施服务包** |
|---|---|---|---|---|
| 目标客户 | 医生个人 / 规培 / 科研自用 | **一个放射科** | 多科室 / 多院区 | 要求定制与现场交付的医院 |
| 典型规模 | 1 机 1 人 | 5–20 人 | 20 人以上 / 多院区 | 任意（按项目） |

### 3.3 关键打包决策与理由

1. **RIS/PACS 直连是分层的"硬边界"。** 它是实施成本最高、最能体现"科室级系统"而非"个人工具"的能力。放在科室版起，既保护实施资源，也让"科室版"这个跳跃显得值。
2. **浮动授权不要免费送。** 浮动授权解决的是"多机、多人、换班"的真实痛点，且**直接决定客户的付费规模**。建议以"含基础座位数（如 5 座）+ 超座阶梯加价"的方式计费，扩容时自动涨价，形成自然增购（NLU）。
3. **定制（规则/词表/台账）默认"选配另计"。** 定制是最消耗小团队人手的活动。把它做成明确的收费项，客户反而认为"你们专业、按需付费"；免费包揽会拖垮交付。
4. **私有化+实施不是"最高版本"，而是"服务包"。** 它可以叠加在科室版/机构版之上。这样报价单能拆成"软件授权 + 服务"，客户看得懂，你也算得清。
5. **设置"评审/迎检加急"选项。** 等级评审有明确时间点，为按期交付支付的溢价是客户最愿意掏的钱之一（§1.2）。

### 4.3 混合模式建议（推荐）

**"一次性实施费 + 年度软件订阅 + 年度运维"三段式**，理由：

1. **一次性实施费**覆盖首年最重的交付成本（部署/联调/培训/定制），避免"首年亏本、指望续费回本"——小团队现金流承受不了这种结构。
2. **年度订阅**是稳定的经常性收入，也是客户可年年立项的科目；续费率高则公司估值逻辑成立。
3. **年度运维**把"版本升级、规则更新、远程支持"明确为持续交付，让"软件更新不额外收费"（现行 `TERMS_OF_SERVICE.md` §2）这句话有成本支撑，也避免把运维义务无限期白送。

**付款节点建议（按医院实际调整，【需市场验证】）**：
预付款 30%–50%（签约/启动）→ 部署与培训完成 30%–40% → 验收合格 20% → 质保金 10%（约定期限后支付）。
> 小团队必须坚持预付：公立医院回款周期长，**全垫资的项目宁可不做**。

## 5. 服务与实施定价

原则：**能标准化的免费或含在版本里，不能标准化的必须单独收费。** 小团队人手有限，免费服务承诺是最大的隐性亏损来源。

| 服务项 | 是否单独收费 | 计价方式建议 | 说明与边界 |
|--------|-------------|-------------|-----------|
| 安装部署（自助/远程） | 科室版含 1 次远程；额外/上门另计 | 远程含；上门 ¥3,000–8,000/天 **【需市场验证】** | 明确"远程需医院提供可远程的通道"（很多内网不具备 → 只能上门，成本要算进去） |
| 安装部署（上门/私有化） | ✅ 收费 | 按人天 + 差旅实报 | 含环境适配、内网联调、权限与账号初始化 |
| RIS/PACS 接口联调 | ✅ 收费 | 按项目 ¥5,000–30,000+ **【需市场验证】** | **风险最高项**。报价前先确认接口文档/厂商配合度，合同中写"若厂商不配合导致的延期不计入我方工期" |
| 数据迁移（历史报告/样本库导入） | ✅ 收费 | 按数据量/复杂度 ¥5,000–30,000 **【需市场验证】** | 需先做样本试导；含一次试导 + 一次正式导入 |
| 规则定制（本院规范） | ✅ 收费 | ¥300–1,500/条 **或** ¥2,000–5,000/人天 **【需市场验证】** | 建议按"条 + 验收用例"交付；写明"新增规则需双方确认规则口径与预期结果" |
| 词表/术语库定制（错别字表、院内缩写） | ✅ 收费 | 阶梯：首批含 N 条，超出按条计 | 与规则定制分开计价，维护更简单 |
| 培训（远程） | 科室版含 2 次 | 超出按次 ¥1,000–3,000 **【需市场验证】** | 分开"医生培训"与"管理员培训"两套材料 |
| 培训（现场） | ✅ 收费 | ¥3,000–8,000/天 + 差旅 **【需市场验证】** | 通常与实际部署同批完成，可打包折扣 |
| 年度运维 / 售后支持 | ✅ 收费（推荐） | 软件年费的 15%–25% **或** ¥1 万–3 万/年 **【需市场验证】** | 含版本升级、规则更新、远程支持、年度巡检；明确响应时段与不含范围 |
| 质控台账定制 | ✅ 收费 | 按模板份数 ¥2,000–10,000/套 **【需市场验证】** | **高毛利项**。与医务科/质控科直接对接，是其核心诉求（§1.3） |
| 迎检 / 等级评审支撑 | ✅ 收费 | 按次 ¥5,000–30,000 **【需市场验证】** | 含台账整理辅导、报表口径对接、现场答疑（**不含**"保证通过"承诺，见 §8） |
| 单机→科室/机构 升级 | ✅ 收取差价 | 补差价 + 实施费 | 老客户升级给折扣，锁住续费 |
| 紧急加急（评审节点） | ✅ 收费 | 在标准价基础上加价 20%–50% **【需市场验证】** | 时间敏感客户的付费意愿最高 |
| 90 天产品试用 | 免费 | — | 产品内置，自助；**不等于**科室级试点（§7） |

**成本红线提醒**：所有"按人天"的报价必须**先估自己的人天**。小团队最常见的失误不是价格报低了，而是**免费承诺了 10 个人天的工作量**。

## 6. 招标与合规前置

### 6.1 谁必须要求器械注册证 / 等保证书，谁可以先落地

**判断逻辑**：不是看医院大小，而是看**这个软件是否进入临床决策闭环、是否被院方纳入需正式准入的信息系统**。

| 场景 | 是否必须注册证 | 是否通常要求等保材料 | 现在能否落地 |
|------|:---:|:---:|:---:|
| 医院要求质控结果**阻断报告签发**、写入诊断内容、与诊断决策绑定 | **必须**（此时已进入器械范畴） | 是 | ❌ **不能**，须等注册 |
| 医院要求接入 HIS/电子病历核心、成为"正式在用信息系统" | 视定性而定，风险高 | **是**（且义务主体是医院） | ⚠️ 谨慎；先补等保配套材料 |
| 公立三级医院走**信息化建设经费公开招标** | 招标文件常要求注册证/检测报告 | 是 | ⚠️ 视招标文件；多数当前无法应答 |
| **科研 / 教学用途**（课题组、科研经费） | 不要求 | 通常不要求 | ✅ **可以**（最佳首单路径） |
| **质量管理用途**：质控辅助、科室质控台账、不阻断签发、不输出诊断结论 | 不要求（**定性需律师/分类界定确认**） | 通常不要求（内网、非核心） | ✅ **可以**（推荐主路径） |
| 单机个人自用 / 规培教学 | 不要求 | 不要求 | ✅ 可以 |
| 单科室非核心系统试点（数据不出科室内网） | 通常不要求 | 通常不要求 | ✅ 可以 |

> **重要**：以上判定是**商务可行性初筛，不是合规结论**。是否落入医疗器械定义，**必须由器械注册顾问/律师确认**（可优先走"分类界定"取得官方口径，见 `docs/COMPLIANCE_GAP_ANALYSIS.md` §1.1 M9、§7.2 R1）。
> **等保的关键事实**：等保的**义务主体通常是医疗机构（网络运营者）**，不是软件厂商。厂商的角色是**让产品具备可测评、可整改的能力**并交付配套文档（部署架构、账号权限矩阵、日志与审计说明、加固建议）。**因此永远不要对外说"我们做了等保三级"**（`docs/COMPLIANCE_GAP_ANALYSIS.md` §1.2 已明确提示）。

| 8 | 渗透测试报告 | ❌ | 中–高 | P2。安全类准入加分项 |

| 10 | 等保定级与测评报告 | ❌ | 高（需外部机构 + 医院配合） | P2。按定级结论推进；**义务主体在医院侧**，厂商配合 |
| 11 | 信创适配（国产 OS / CPU / 数据库）与相关证明 | ❌ | 中–高 | P2。公立与政务相关场景越来越常要求；**需市场验证具体范围** |
| 12 | ISO 13485 / 风险管理等体系文件 | ❌ | 高 | P3。仅走器械注册路线时需要 |
| 13 | **二类医疗器械注册证** | ❌ | **很高（周期 12–24 个月）** | P3。**只有确认定性为器械、且要打正规临床市场时才启动** |
| 14 | 数据合规材料（PIA、DPA、导出审批表） | 🟡 部分 | 中 | P1–P2。与是否做器械无关，**建议尽早补齐** |

**推荐获取顺序（三步走）**：
- **第 0–3 个月（能签单）**：公司主体 + 发票 → 软著 → 口径统一 + 律师意见 → 现有商务文档打包成"投标资料册"。
- **第 3–9 个月（能应答招标）**：第三方检测报告 → 1–3 家试点案例与用户报告 → 等保配套材料包 → 渗透测试（可选）。
- **第 9–24 个月（能进核心场景）**：等保定级与测评（按需）→ 信创适配 → 若定性为器械，启动注册（**不要把 12 个月拿证写进任何材料**）。

### 6.3 投标技术参数的正确写法（合规引导）

可以**写清能力要求**来体现产品优势（如"支持确定性规则引擎的本地化质控""支持离线 OCR""支持数据不出院内网的本地部署""支持与 RIS/PACS 对接"），但**不得设置排他性、指向性条款**（如指定品牌、指定独有技术名词、指定只有你能满足的参数）。这既是合规要求，也是防止被质疑与废标。

## 7. 低成本获客路径

小团队缺实施人手，**获客策略必须与交付能力匹配**：宁可慢，也不要一次接三个装不完的单。

### 7.1 四步递进路径

```
① 单科室试点（1 个放射科，1–3 个月，低价或免费）
        ↓  产出：脱敏试点报告 + 用户反馈 + 使用数据
② 数据说话（用科室自己的数据讲效果）
        ↓  产出：可对外的案例材料（需客户书面授权）
③ 科室间扩展（同院第二个科室 / 同区域兄弟医院）
        ↓  产出：区域口碑 + 多案例
④ 医务科 / 质控科立项（进入台账与迎检场景，价格上一个台阶）
        ↓  产出：正规合同 + 年度续费 + 机构版机会
```

### 7.2 试点报价策略

| 项 | 建议 | 理由 |
|---|------|------|
| 试点价 | **¥0–5,000**（3 个月），或"转正式合同全额抵扣" | 低价换数据与案例，不换现金；抵扣可显著提高转化率 |
| 必须签的文件 | **试点协议**（范围、期限、双方义务）+ **数据使用与保密条款** | 没有协议，"试点"会变成无限期免费使用 |
| 试点范围 | 明确限定 **1 个科室、N 个账号、约定功能范围** | 防止范围蔓延（小团队最容易被拖垮的地方） |
| 试点期限 | 明确 **1–3 个月** 与到期动作（续费/升级/终止） | 到期必须给出结论，避免"永远在试用" |
| 试点交付 | 部署 + 培训 + 月度小结 | 让客户感到"这是项目，不是下载了个软件" |
| 试点转正 | 试点价可全额抵扣首年费用；转正客户享老客户价 | 降低决策门槛，锁定续费 |
| 客户选择 | 优先选**有意愿出案例、有明确质控痛点、信息科配合度高**的科室 | 试点成功的关键是客户配合度，不是医院大小 |

### 7.3 90 天试用与付费试点的配合

产品已内置 **90 天试用**（机器绑定 + 试用锚点，删除 `license.dat` 不能重置）。要把它当**产品自传播工具**，而不是科室级获客手段：

| 场景 | 用哪个 | 配合方式 |
|------|-------|---------|
| 医生个人体验 | **产品 90 天试用** | 自助下载，扫码/加群获取；不签协议，转化到单机版或科室版 |
| 科室级试点 | **试点协议 + 限时授权码** | 不要依赖内置 90 天试用——它会**自动开始、无法重置**，客户容易本能地"再等等"而错过推动窗口。用专门的试点授权码 + 明确到期日，制造紧迫感 |
| 展会/路演现场 | 产品试用 + 演示机 | 现场演示用样例数据，**不要**在演示机留存真实报告 |
| 试用到期后 | 转化动作 | 到期前 7 天由人（不是弹窗）联系，给出"科室版试点"或"单机版"两条路径 |

> 运营提示：试用锚点写入注册表与用户目录，"删文件重置"不可行——这对商务是好事（防止无限白嫖），但**不要在客户面前强调"我们防着你"**，表述为"试用期以首次运行时间计算"即可。

### 7.4 案例包装建议

**可以写**（有客户书面授权、数据脱敏的前提下）：
- 场景描述："某三级医院放射科，月报告量级别为 ____，参与医生 ____ 人"（**具体数字需客户同意后填**）。
- 过程描述：部署方式（内网自托管）、使用流程（报告质控 → 看板 → 导出）、覆盖的规则类型（如"性别矛盾、左右混淆、描述-结论矛盾、单位错误、错别字等"）。
- **可核验的客观计数**：如"试点期共质控 N 份报告，系统提示 M 处待确认问题，经医生确认为有效提示 X 处"——**只报计数与类别，不报准确率、不报漏诊率**（§8）。
- 客户主观评价（引用原话，须书面同意）。

**不可以写**：
- ❌ "准确率 XX%""漏诊率下降 XX%"（未做临床验证，无依据）
- ❌ "提升诊断质量""降低医疗风险""避免误诊"（临床结局承诺，红线）
- ❌ 未经授权使用医院名称、科室名、医生姓名、真实报告内容
- ❌ 把"用户反馈"包装成"临床验证结论"

**案例材料的三个版本**：一页纸（给科室看）、三页版（给医务科看，含台账与迎检价值）、投标附件版（含部署架构与验收要点）。同一事实，三种详略。
