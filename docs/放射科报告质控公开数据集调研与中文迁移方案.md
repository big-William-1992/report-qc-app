# 放射科报告质控公开数据集调研与中文迁移方案

> 目标：在「中文报告 + 确定性规则（R1–R23） + 本地 LLM 质控层」的框架下，
> 回答「没有中文标注数据时，如何构造训练集」这一问题。
> 结论：**英文公开错误集做"方法种子" + 本项目确定性引擎做"规则蒸馏" + 本地 teacher 合成"中文错例"**，
> 三者合并即可产出 Qwen-3B 微调用的 alpaca 训练集，且数据全程不出院。

---

## 一、公开数据集调研摘要

| 数据集 | 规模 | 模态 | 语言 | 错误类型 | 获取方式 |
|---|---|---|---|---|---|
| **CorBenchX** (2025) | 26,326 错报对（单错 24k + 多错 2k） | 胸片 | 英 | Omission / Insertion / Spelling / Side Confusion / Other（含 span+描述） | GitHub `Liqq1/CorBenchX`；数据投 PhysioNet（评审中） |
| **ReXErr-v1** (2024) | 20 万+ 合成错报到（GPT-4o 注入） | 胸片 | 英 | report/sentence 两级 + error_type | PhysioNet（凭证）；`rajpurkarlab/ReXErr-V1` |
| **llm4proofreading** (2025) | 1,656 合成 + 614 MIMIC（307 对错/正） | 胸片 | 英 | **negation / left-right / interval change / transcription** | `bionlplab/llm4proofreading` |
| **MedErr-CT** (2025) | ~4 万 错误 VQA 样本 | CT(3D) | 英 | Omission / Insertion / Direction / Size / Unit / Typo | `babbu3682/MedErr-CT` |
| **ReXVal** | 200 对（AI 生成 vs 真报告） | 胸片 | 英 | 6 类，6 名放射科医生标注 | PhysioNet（凭证） |
| **RadEvalX** | 100 份（IU-Xray） | 胸片 | 英 | 8 类 + 严重度 | PhysioNet |
| **ReFiSco-v0** | 60 例（MIMIC） | 胸片 | 英 | 行级严重度 + 修正 | PhysioNet |
| **Sqator**（中文，2025） | 12,013 份中文报告（X线/CT/MRI）juniors vs seniors + span 级修订 | 中文 | **中** | 弱监督修订对 | 学术 arXiv 2508.08876，**数据集大概率未公开**，需联系作者 |

### 关键结论
1. **可直接用于"方法种子"的英文集都不含中文**，且多依赖 MIMIC-CXR，受 PhysioNet 凭证 DUA 约束（禁止再分发原始报告，仅给代码/提示词）。
2. **中文公开质控数据集基本空白**：仅检索到 Sqator 一篇中文工作，且未公开；通用中文医学 NLP（CBLUE / CMEIE）是实体/关系抽取，不是"报告错误检测"，目标不匹配。
3. **评测框架（非训练集）**：`RadFact`（微软，事实性度量）、`RadEval` + `RadEvalExpertDataset`、`CREPE/CLEAR/RadCliQ`，可用于 LLM 层上线前的事实性评估。

## 二、中文迁移方案（三步走）

```
                 ┌─────────────────────────────────────────────┐
   英文错误集 ──►│ ① 方法种子（dataset_adapters 对齐 taxonomy） │
   (CorBenchX/   │   产出 alpaca 样本（英文，作 few-shot/结构种子）│
    ReXErr/      └─────────────────────────────────────────────┘
    llm4proof)                         │
                                       ▼
   中文干净报告 ──►┌──────────────┐   ┌──────────────────────────────┐
   （本院/脱敏）   │ ② 规则蒸馏    │   │ ③ 本地 teacher 合成中文错例    │
                  │ RuleEngine    │   │  synth（确定性，可验证）       │
                  │  → 高精银标    │   │  或 Ollama 微调 teacher（生产） │
                  └──────┬───────┘   └──────────────┬───────────────┘
                         │                          │
                         └──────────┬───────────────┘
                                    ▼
                        data/qc_sft.jsonl  ──►  LlamaFactory 训练 Qwen-3B
```

### 步骤 ①：英文错误集 → 方法种子
- 脚本：`tools/dataset_adapters.py`
  - `corbenchx_records` / `rexerr_records` / `llm4proofreading_records` 分别解析三种格式；
  - 错误类型统一映射到本项目 taxonomy（见下表）；
  - 输出对齐 `train/dataset_info.json` 的 alpaca 字段。
- 说明：英文样本直接喂中文模型效果有限，**生产建议先机翻为中文**，或仅作为 few-shot 种子；本验证为证明链路先直接使用。

### 步骤 ②：确定性引擎 → 规则蒸馏（高精银标）
- 在中文干净报告上跑 `RuleEngine`，把命中的 R1–R23 作为银标（`confidence=1.0`），天然高精确、零标注成本。
- 对应 `build_qc_dataset.py --mode rule` 已存在；本流水线在 `step_rule_distill` 中复用。

### 步骤 ③：本地 teacher → 合成中文错例
- **确定性替身（已验证）**：`tools/cn_error_synth.py` 对干净报告注入可控临床错误
  （左右混淆 / 错别字 / 性别矛盾 / 否定词翻转），产出 (错误报告, 期望发现) 训练对，格式与 `llm_qc` 输出完全一致。
- **生产 teacher（待接入）**：`--teacher llm` 调用本地 Ollama/vLLM 微调后的 Qwen，`run_llm_qc` 产出发现。
  用户拿到训练好的模型后，只需改 `src/llm_config.json` 的 `model`/`provider` 再跑 `--teacher llm` 即可，无需改代码。

### 错误分类映射表（英文集 → 本项目 taxonomy）
| 英文集错误类型 | 本项目 taxonomy | 对应规则 |
|---|---|---|
| Omission | `R15-PRESENCE` / `R18-COVERAGE` | R15/R18 |
| Insertion | `R12-SENTENCE` | R12 |
| Spelling Error / transcription | `R8-TYPO` | R8 |
| Side Confusion / left-right | `R2-LATERALITY` | R2 |
| negation | `R5-CONSISTENCY` | R5 |
| interval change | `R13-TEMPORAL` | R13 |
| Other / 未识别 | `L1-OTHER` | — |

### 数据格式对齐（alpaca）
```json
{"instruction": "你是资深放射科质控专家……", "input": "含错误的报告",
 "output": "[{\"error_type\":\"R2-LATERALITY\",\"location\":\"左肺\",\"severity\":\"high\",\"confidence\":1.0,\"rationale\":\"左右混淆：将 '右肺' 误写为 '左肺'\"}]"}
```
对应的 `train/dataset_info.json` 已声明 `prompt/query/response` 列映射。

## 三、流水线用法

```bash
# 1) 仅验证链路（无需任何外部数据，内置样例）
python3 tools/build_cn_dataset.py --demo --out /tmp/qc_cn_demo.jsonl

# 2) 真实构造：中文干净报告目录 + 英文种子目录 + 确定性 teacher
python3 tools/build_cn_dataset.py \
    --chinese-reports /path/to/clean_cn_reports \
    --english-seeds   /path/to/en_error_sets \
    --teacher synth --out data/qc_sft.jsonl

# 3) 接入真实微调 teacher（需先起 Ollama/vLLM 并改 src/llm_config.json）
python3 tools/build_cn_dataset.py \
    --chinese-reports /path/to/clean_cn_reports \
    --teacher llm --out data/qc_sft.jsonl
```

### 步骤 ③ 之扩展：LLM 错误注入（ReXErr 方法论）+ 回检闭环
除确定性合成器外，本仓库新增「注入模式」（`tools/llm_inject.py`），由 LLM 主动往**干净**报告注入临床错误，再回检过滤：
- `inject_errors(client, text)`：调用本地/院内 LLM（或脱敏云 API），要求输出 `{injected_report, errors:[{error_type,location,severity,rationale}]}`；
- `verify_injection(...)`：用确定性 `RuleEngine` 回检，仅保留「错误真落在文本中且可被质控检出」的样本，过滤噪标；
- `build_cn_dataset.py --inject`（接真实 LLM）/ `--self-test-inject`（离线模拟，合成数据验证全链路）。

合规边界：**真实 PHI 报告只经院内/本地模型注入；公有云 API（如 hy3）仅用于脱敏/合成样本做方法论验证**，切勿传真实报告。

验证（离线自测，`--self-test-inject`，合成数据，无需网络）：

  英文种子 2 | 规则蒸馏 3 | teacher合成 3 | LLM注入 3

样例摘录（teacher 合成的中文错例，与 `llm_qc` 输出同构）：
- `右肺上叶 → 左肺上叶` + `患者男 → 患者女` ⇒ `[R2-LATERALITY, R1-GENDER]`
- `肝左叶 → 肝右叶` ⇒ `[R2-LATERALITY]`
- `未见占位 → 可见点位` + `男→女` + `未见→可见` ⇒ `[R8-TYPO, R1-GENDER, R5-CONSISTENCY]`

## 四、合规与注意事项
- 所有训练数据在**本院内网生成**，PHI 不出院；PhysioNet/MIMIC 系数据仅作"方法参考"，进训练前须脱敏且遵守 DUA。
- `--teacher llm` 的 teacher 必须本地部署（Ollama/vLLM），禁用公网 API 处理真实报告。
- 英文种子建议机翻为中文再混入，避免中英混杂影响中文小模型收敛；方法种子占比建议 ≤20%。
- 最终精度以本院放射科医生抽检为准（真实分布评测优先于公开英文基准）。

## 五、后续
1. 用户拿到真实中文报告语料 → 填 `--chinese-reports`，跑 `--teacher llm` 产出中文训练集。

3. 训练：`train/train.sh`（LlamaFactory LoRA，Qwen2.5-3B-Instruct）；产物经 `/api/v1/qc/full` 灰度上线。
4. 用 `RadFact` 或医生抽检做 LLM 层事实性回归，防止蒸馏后的小模型幻觉。
