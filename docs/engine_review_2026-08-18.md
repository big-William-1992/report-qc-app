## 🔴 高危

### H1　R8 危险错字映射 + auto_fix 默认勾选 → 语义反转/文本破坏
- **位置**：`engine.py:700`（`"已见": "未见"`）；`assets/rules_config.json:60, 88-95`（`有肺→右肺`、`直接→直径`、`简易→建议`、`结界→结节`、`肋膜→胸膜`）；`learn_typo` 797-818（无常用词校验）；`auto_fix` 1029-1046（直接替换）；`app.py:3434`（预览默认 `BooleanVar(value=True)` 全勾选）
- **问题**：错词表把**本身是常用合法词**的字串当作错字。实测：
  - `auto_fix("患者症状较前已见好转，右肺上叶见小结节")` → `"患者症状较前未见好转"`——**"已见→未见"把含义反转**（已好转变未好转）
  - `auto_fix("患者有肺气肿病史，…")` → `"患者右肺气肿病史"`——**"有肺→右肺"语义篡改**
  - `直接→直径`（"直接增强扫描"被改）、`简易→建议`、`结界→结节`（可能是姓名/专名）、`肋膜→胸膜`（肋膜是合法解剖词）
- **触发场景**：任何含"已见/有肺/直接"的正确句子，用户在自动修正预览里一键全选（默认即全选）→ 报告被静默改写，属**数据破坏级**缺陷。
- **修复建议**：
  1. 立即删除 `已见→未见`（高危反转），并把 `有肺/直接/简易/结界/肋膜` 移出默认表或标为"仅提示不自动替换"；
  2. `learn_typo` 入库前校验：错词若命中高频白名单（`highfreq_lexicon`）/常见中文词表则拒绝或要求二次确认；
  3. `auto_fix` 对"wrong 本身是合法常用词"的词条不参与自动替换，只给提示；
  4. GUI 预览对这类高风险改动默认不勾选并红色标注。

### H2　R19 归一化坐标错位 → auto_fix 在原文上按错误偏移替换
- **位置**：`engine.py:1456-1461`（`norm_text` 删除 CJK 间标点/空格）、`1498-1532`（R19 的 `span=(s,e)` 取自 **norm_text** 坐标）、`1020-1047`（`auto_fix` 用该 span 直接切**原文** `text[s:e]` 并替换）
- **问题**：实测 `"磨 玻 璃影，磨．玻．璃结节"` → norm `"磨玻璃影磨玻璃结节"`（长度 17→11）。只要文本中存在被归一化删除的字符，R19 命中片段的偏移相对原文整体错位。`auto_fix` 会在错误位置插入替换词，破坏报告文本；同时 `_preview_autofix` 展示的上下文（`text[s-12:e+12]`）也是错的。
- **触发场景**：OCR 噪声文本（字间空格/全角点）、且生产机安装 pypinyin 使 R19 生效。
- **修复建议**：归一化时记录「norm 位置 → 原文位置」映射表（逐字符 build offset map），R19 产出前把 span 反算回原文坐标；或 R19 类 Finding 一律不参与自动替换（只提示）。`auto_fix` 末尾加一致性校验：替换后片段应与 suggestion 相同且替换点前后文合法。

### H3　R22 正则灾难性回溯（ReDoS）
- **位置**：`engine.py:1331-1338`（两分支均为 `[，,、:：\s]*` + `(?:…)?` + `\s*` + `约?` + `\s*`，连续 3 个空白/可选量词）
- **问题**：实测 `"结节" + n 个空格`：n=400 → 174ms，n=1000 → **进程挂死 >60s**，n=4000 → 约数分钟，复杂度 O(n³)（finditer 在每个锚点位置回溯）。
- **触发场景**：报告中"结节/肿块/占位/肿物"后跟长空白或长标点串（OCR 粘贴文本的连续空格、批量导出的排版噪声很常见）→ 单次质控卡死 GUI 数分钟。
- **修复建议**：把连续空白量词合并为单个字符类，例如：
  ```python
  r"(结节|肿块|占位|肿物)[，,、:：\s]*(?:大小|直径|径线|体积|最长径)?[，,、:：\s]*约?[，,、:：\s]*(\d+…)(…)"
  ```
  或对输入做长度上限/空白折叠预处理（`re.sub(r"\s+", " ", text)`）。

### H4　"影像所见"等常见描述段标题未被识别 → R5/R2/R12 静默漏检
- **位置**：`engine.py:901-905`（NER `SECTION_MAP` findings 分支仅 `检查所见|影像描述|表现|…`，缺 `影像所见/超声所见/CT所见/MRI所见`）；`921-925`（`_section_of` 对标题前实体回退返回 `sections[-1][0]`，即 **impression**）；`_split_for_r5` 1216 同样缺该标题
- **问题**：实测 `"影像所见：左肺上叶见结节。\n影像结论：…"` → NER 把 `左肺上叶` 标成 **impression** → `_r5_consistency` 的 `e.section != "findings"` 过滤 → **R5 返回 0 条**；同一文本把标题换成"检查所见" → R5 正常返回 1 条。R2 的 NER 分支、R12 的 NER 器官合并分支同样受影响。
- **触发场景**：所有以"影像所见/超声所见"为描述段标题的报告（中文放射报告最常见写法之一）→ 描述-结论一致性规则静默失效。
- **修复建议**：将 NER 与 `_split_for_r5` 的标题表抽成共享常量（单点维护），补 `影像所见|超声所见|CT所见|MRI所见|MR所见`；`_section_of` 对无归属位置回退到 `"findings"` 而非 `sections[-1]`；并统一两处切分实现，消除 `meta` 段与 findings 文本不一致的问题。

## 🟠 中危

### M1　`_extract_lesion_count` 多位数截断 → R14-COUNT 误报
- **位置**：`engine.py:614-624`（`([一二三四五六七八九十两双单\d])` 单字符捕获）；使用处 1696-1702
- **实测**：`"见约10枚结节"` → 0；`"见12个结节"` → 2。10 vs 12 → 0 vs 2 → 误报"数量前后不一致"；1 vs 10 → 1 vs 0 → 误报。
- **修复**：捕获组改 `(\d+|[一二三四五六七八九十两双单])`；`_cn_to_int` 对阿拉伯数字串直接 `int()`。

### M2　`_region_assertions_in_section` 边界截断顺序错误 → R17 假阳性
- **位置**：`engine.py:347-351`（按 `("。","；",";","\n")` 顺序 find 到第一个即 break，而非取所有边界类型中的**最早位置**）
- **实测**：`"左肺无异常；右肺见结节。"` → 左肺被标 **positive**（截断在句号而非分号，把右肺分句的"结节"吞进左肺窗口）→ 结论写"左肺未见异常"时 R17 误报"描述异常、结论正常"。
- **修复**：`_bi = min((after_big.find(b) for b in _bnd if after_big.find(b) > 0), default=len(after_big))`；或统一按 `[。；;\n]` 切一次取首个。

### M3　R17 两处系统性漏报
- **位置**：`engine.py:1772-1797`（逐部位仅按精确 `(key, side)` 匹配）；`352-354`（`is_normal` 只查"未见异常"等，缺"无异常/无明显异常"）；`506-521`（`_is_negative_claim` 只查 POSITIVE_STRONG 被否定，而"异常"不在 POSITIVE_STRONG）
- **实测**：
  - `"右肺见结节"` vs 结论 `"两肺未见异常"` → **不报**（(lung,bilateral) 正常不覆盖 (lung,right) 阳性）
  - `"左肺无异常"` vs 结论 `"左肺见结节"` → **完全不报**（`NORMAL_CLAIM` 含"无异常"但三个判定函数均未覆盖）
- **修复**：(a) R17 比对时将 bilateral 正常断言展开为覆盖 left/right；(b) `is_normal` 检查补 `"无异常|无明显异常"`，`_is_negative_claim` 增加对 NORMAL_CLAIM 短语（无阳性词）的识别。

### M4　R15-2 双侧/多部位阳性描述误报
- **位置**：`engine.py:1722-1737`（同一器官取"单侧句"两两比对，方位不同即报）
- **实测**：`"左肾见小结节。右肾见小结节。"` → 误报"同一器官肾前后方位不一致"。这是完全正常的双侧病变描述。
- **修复**：要求两侧句子描述**同一征象词**（如两侧都提"积水"）且一侧带否定才构成矛盾；或一侧为 normal/阴性声明时才报。

### M5　R14-NATURE 假阳性："炎性浸润" / "CA125"
- **位置**：`engine.py:378-379`（MALIGNANT_MARKERS 含"浸润"与无词边界的 "ca"/"mt"）；`627-638`（`_has_marker_unnegated`）
- **实测**：`"局部炎性浸润"` → mal=True（良性语境被当恶性）；`"CA125正常范围"` → mal=True（"ca" 子串命中）。与结论"良性"配对即误报 R14-NATURE。
- **修复**：从恶性标记中移除"浸润"（或要求"浸润性癌/浸润癌"组合）；"ca"/"mt" 改用词边界（如 `\bca\b`，且仅大写 CA/MT 后跟空白/句末才认）；`_has_marker_unnegated` 的否定豁免正则补 `排除`（"排除恶性"现在是漏网）。

### M6　R9 豁免词缺"待排/待查" → 鉴别诊断表述误报
- **位置**：`engine.py:1584-1585`（豁免词仅 `待定/不除外/鉴别/除外`）
- **实测**：`"考虑良性可能，恶性待排"` → 误报 R9-CONFLICT（良性 vs 恶性互斥）。"恶性待排"是鉴别诊断的**标准合法表述**。
- **修复**：豁免词表补 `待排|待查|需排|性质待定`。

### M7　`_organ_sides_in_text` 不识别"左侧X/右侧X"（带"侧"）
- **位置**：`engine.py:656-661`（`左\s*{organ}` 要求紧邻）；影响 R2 文本分支 1127-1128、R15 1724
- **实测**：`"左侧卵巢见囊肿"` → `set()`（应为 `{left}`）；`"左卵巢"` → `{left}`。系统性地漏检"左侧/右侧+器官"的最常见写法。
- **修复**：改为 `左\s*侧?\s*{organ}`（同时保留 `{organ}\s*左` 反向匹配），并与 `_detect_side_in_text` 覆盖对齐。

### M8　R5 器官族缺"双肺/两肺/肺" → 结论用泛称时误报
- **位置**：`engine.py:1192-1194`（`fam_organs` 仅来自 ANATOMY_SYNONYMS 的"左肺/右肺/肺叶"词）
- **实测**：`"检查所见：左肺上叶见结节。"` + 结论 `"双肺纹理增多。"` → 误报"未就该器官给出对应结论"（"双肺"不在 fam_organs；结论词表又无"增多"）。
- **修复**：把 `双肺|两肺|肺|肺野|肺实质` 并入 lung 族（复用 REGION_LEXICON lung 的 extra），并对泛称结论适当放宽。

### M9　`save_rules_config` 非原子写 + `learn_typo` 无锁读改写 → 并发丢更新/损坏
- **位置**：`engine.py:790-794`（`open(path,"w")` 直接写）、`797-818`（load→modify→save）、`778-784`（load 时合并默认词表）
- **实测**：2 线程各调用 50 次 `learn_typo` → 期望 100 条新词，实际仅 97 条（**丢更新**）；进程中途崩溃时 `"w"` 模式会留下截断/半写的 JSON。
- **触发场景**：多实例部署（两个桌面实例/未来 Web 服务并发学词、保存忽略名单）。
- **修复**：写临时文件 + `os.replace()` 原子替换；模块级 `threading.Lock` 保护"load→modify→save"临界区；`learn_typo` 在锁内完成。

### M10　R4 VALID_UNITS 缺 MRI/CT 常用单位 → 误报
- **位置**：`_lexicons.py:63`（`VALID_UNITS`）、`engine.py:952-956`（单位实体抽取）、`1167-1172`（R4）
- **实测**：`"1.5T磁共振"`、`"120kV"`、`"100mAs"`、`"10min"`、`"100mg/ml"` 均会被 R4-UNIT 报"非常规单位"——这些是 MRI/CT 的**标准单位**。
- **修复**：VALID_UNITS 增补 `t/kv/kva/mas/min/ml/s/mg/ml/mmol/l/mg/dl…`，或改为"白名单外单位仅提示不扣分"。

## 🟡 低危

- **L1** `_r12_same_region` 否定判定仍用旧 `endswith` + 5 字窗口（`engine.py:577-579`），与 2026-08-18 的 `_NEG_BEFORE_POS_RE` 修复不一致；存在其它阳性词时，"左肺未见实质性占位，左肺正常"类句会假阳性。建议复用 `_word_effectively_present`。
- **L2** R22 不匹配三维径线 `"4.2×3.1×2.0cm"`（`engine.py:1331-1338`）→ 三维测量漏报。修复：径线数改为 `(?:\s*(?:×|x|\*)\s*\d+(?:\.\d+)?){1,2}`。
- **L3** findings 标题含"表现"子串（`engine.py:1216`、`902`、`1597`）：患者头"临床表现：咳嗽"会被当成描述段标题 → R10 漏报"缺描述段"、`_split_for_r5` 的 f0 从"临床表现"起切。建议标题正则限定 `(?:^|\n)\s*(?:影像|超声|CT|MRI|MR)?所见|检查所见`。
- **L4** R18 注释与代码矛盾（`engine.py:1309-1314`）：注释称 R20"不豁免正常声明"，代码 `if missing and not _claims_normal(combined)` 实际豁免 → "只写肺纹理增多 + 印象未见明显异常"的胸部报告漏过必查要素检查。需确认设计意图并统一。
- **L5** R19 性能（安装 pypinyin 后）：每滑窗 `_hf_segment_candidates` 线性扫 ~300 词白名单（`highfreq_lexicon.py:465-467`）+ `_inside_covered` 每次重建 `[c[0] for c in cov]` 列表（`engine.py:1488-1496`）+ O(L²) 滑窗 → 数千字报告可达秒级。建议：白名单预建 set、covered 区间一次排序后二分、限制 CJK run 长度、未命中窗口提前跳出。
- **L6** 死代码/死导入：`_REGION_ALIAS_RE`（`engine.py:289`）编译后从未使用；`NEGATIVE_MARKERS`（`_lexicons.py:70`）无任何使用点；`_zh_norm_text`（`engine.py:33`）导入未用。建议删除或补用。
- **L7** `run()` 内 `_split_for_r5` 被调用 9 次（`engine.py:997, 1014, 1110, 1177, 1246, 1284, 1554, 1641, 1710`），每次全文本正则扫描；其中 1014 行与 997 行结果完全相同。建议 run() 计算一次 secs 传入所有规则。
- **L8** `score()`/`score_summary()` 实测无除零、无异常（`engine.py:1858-1880`），但：(a) "及时性"恒 100，是无扣分维度的死维度；(b) 未知 severity（如 config 自定义字符串）扣 0 分无任何提示，准确性评分会失真；(c) "规范性"仅 90/100 两档。建议未知 severity 告警或 clamp 到 low。

## 💡 建议

1. **词表安全护栏**：`learn_typo` 增加最小长度 2 + "错词命中高频白名单/常用词表则拒绝入库"；对已入库危险词条提供一键"移出并加入黑名单"。
2. **标题表单点维护**：NER `SECTION_MAP` 与 `_split_for_r5` 共用一份编译后的标题正则常量，避免两套切分漂移（本次 H4/L3 均源于此）。
3. **对象复用**：`ChineseRadiologyNER` 无状态，`run()` 内每次新建无必要（可模块级单例）；`RuleEngine()` 每次构造读盘 `rules_config.json`，若未来上 Web 服务建议缓存 + `reload_rules()` 显式刷新。
4. **否定语义统一**：`_has_positive` / `_is_negative_claim` / `_word_effectively_present` 三份近似代码合并为一个返回 `(has_pos, has_neg)` 的函数，并把 POSITIVE_STRONG 预编译为 Trie 或单次正则，避免每次全文扫描 60+ 词。
5. **auto_fix 后置校验**：替换完成后对每个改动点验证"替换结果与 suggestion 一致、且 wrong 不是常用词"，发现异常则撤销该条并降级为提示。

## 总结（最重要 3 条优先修）

1. 🔴 **auto_fix 数据破坏**：删除/禁用 `已见→未见`、`有肺→右肺`、`直接→直径` 等危险映射并加固 `learn_typo`；同时修复 R19 归一化坐标错位（H1+H2）——当前一键勾选即可把"较前已见好转"静默改成"较前未见好转"，是最紧急的缺陷。
2. 🔴 **R22 正则回溯卡死**（H3）：合并连续 `\s*` 量词，消除"结节+长空白→分钟级挂死"的 ReDoS。
3. 🔴 **"影像所见"等描述段标题漏识别**（H4）：统一并补齐 NER/切段标题表，否则最常见的报告格式下 R5/R2/R12 静默失效，质控形同虚设。

> 其余中危项建议按 M2（R17 假阳性）、M1（R14 数量误报）、M7（左侧X漏检）、M9（并发写）的顺序排期；M3 的 R17 双侧/无异常漏报直接影响"描述-结论矛盾"检出率，建议与 H4 一并处理。
