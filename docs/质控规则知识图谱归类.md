# 质控规则 · 知识图谱归类方案

*基于 `anatomy_lexicon.py`（RadLex 器官族 + 侧别建模 + UMLS CUI）与 `zh_ner.py`（征象/随访实体）的本体，对 `engine.py` 全部规则做 `(实体类型 × 关系类型)` 归类。*

---

## 一、结论

**能，而且应该。** 当前规则是 `R1–R18` 按"发现顺序 + 表面症状"平铺编号，和知识图谱**没有结构性挂钩**——所以才会出现"左右矛盾被 5 条规则覆盖、正常性矛盾被 4 条规则覆盖"的重复观感。

知识图谱已经定义了实体类与关系轴（器官族、`lat`=B/R/L/M、`side_ok`、RadLex RID、UMLS CUI、CUIA…），规则完全可以**挂到图谱的"实体类型 × 关系类型"二维坐标上**。归类后，原本看似零散的 18 条规则会自动聚成清晰的"关系族"，重复感从结构上消失，且前端可按图谱维度（如"只看所有左右侧关系""只看所有正常性关系"）灵活分组。

> 衔接上一轮《重复分析与整改计划》：方案 B 要合并的"群集 C"（`R11-ABNORMAL / R14-NORMAL / R17-PERREGION`），在图谱归类里**正好全部落在 `(AnatomicalSite/Observation, hasNormality)` 这一个关系格**——这从本体层面证明了"它们本就是同一条关系规则、只是兜底层级不同"，合并有充分依据。

## 二、知识图谱已有的本体（归类底座）

从代码提炼出的实体类与关系，是归类的坐标，不是新造概念：

### 实体类（Node Class）
| 实体类 | 来源 | 关键属性 |
|---|---|---|
| `Patient` | meta（性别/年龄） | gender, age |
| `AnatomicalSite` | `ANATOMY` 器官族 | `lat`(B/R/L/M)、`side_ok`、RadLex `rid`、UMLS `cui`、中英文别名 |
| `Observation` | `zh_ner`（征象/测量/良恶性） | sign, measurement, nature(benign/malignant) |
| `Temporal` | `zh_ner`（随访） | followup_timeframe |
| `ReportDocument` | 报告结构 | sections, template, text_quality |

### 关系类型（Edge / Relation）
| 关系 | 语义 | 图谱属性支撑 |
|---|---|---|
| `hasGender` | 实体性别属性 vs 患者性别 | `GENDER_ORGANS`（男女专属器官） |
| `hasLaterality` | 左右侧一致性 | `ANATOMY.lat` / `side_ok` |
| `hasNormality` | 正常/异常一致性 | 段落/部位级 normal/positive 断言 |
| `consistentWith` | 同一实体跨段/跨结论一致 | 实体归一化（同义词→规范节点） |
| `present` | 应存在项是否缺失 | 模板必填段、登记部位、区域器官 |
| `hasQuality` | 表面质量（错别字/单位/互斥） | 词典 |
| `hasTemporal` | 随访时限是否给出 | `zh_ner` followup 实体 |
| `contradicts` | 显式互斥冲突 | `rules_config.conflicts` |

## 四、归类后自然浮现的"关系族"

平铺的 `R1–R18` 编号被替换为**按关系归类的族**，重复感从结构上消除：

- **`hasGender` 族**：`R1-GENDER / R7-INTERNAL / R11-GENDER / R12(男女)` —— 统一校验"性别属性一致性"
- **`hasLaterality` 族**：`R2 / R11-SIDE / R14-SIDE / R15-SIDE` —— 统一校验"左右侧一致性"（图谱 `side_ok` 控制哪些器官参与）
- **`hasNormality` 族**（= 上一轮群集 C）：`R17-NORMALITY`（由 `R11-ABNORMAL / R14-NORMAL / R17-PERREGION` 合并而来，保留逐部位/段级兜底多粒度判定）`+ R15-NORMAL` —— 统一校验"正常性矛盾"。**方案 B 已完成合并**，群集 C 现以单一 `rule_id` 呈现，重复告警消除。
- **`consistentWith` 族**：`R5 / R14-NATURE / R14-COUNT / R17(逐部位)` —— 统一校验"跨段/跨结论一致性"
- **`present` 族**：`R6 / R10 / R18` —— 统一校验"完整性/应存在项"
- **`hasQuality` 族**：`R3 / R4 / R8 / R9` —— 统一校验"表面质量"
- **`hasTemporal` 族**：`R16` —— 随访时限

> 注意：图谱 `side_ok` 字段（B/R/L/M）直接决定了 `hasLaterality` 族**哪些器官要查、哪些不查**（中线器官如心/气管不参与）——这正是"按知识图谱要求归类"比 R1–R18 编号强的地方：规则的作用范围由图谱属性驱动，而非硬编码。

## 五、落地建议（若实施）

### 5.1 给规则加 KG 元数据（不动 rule_id，向后兼容）
每条规则/Finding 增加一个结构化标注：
```python
KG_META = {
    # 关系族 → 展示分组键
    "R17-NORMALITY": {"entity": "AnatomicalSite", "relation": "hasNormality"},  # 已合并群集 C
    "R15-NORMAL":    {"entity": "AnatomicalSite", "relation": "hasNormality"},
    "R2-LATERALITY": {"entity": "AnatomicalSite", "relation": "hasLaterality"},
    # ... 其余同理
}
```
`Finding` 增加可选字段 `kg_relation`（来自该映射），SPA 看板即可按 `kg_relation` 维度分组/筛选，而非依赖易碎的 `rule_id` 前缀解析。

### 5.2 规则编号与图谱解耦
- `rule_id` 保留（兼容历史 ignores、样本库、前端），仅作为稳定主键。
- 对外展示与分组改用 `kg_relation` / `entity` 维度。
- 重编号（如"关系-序号"）**不建议**——会破坏现有 ignores 与样本数据，代价大于收益。

### 5.3 与方案 B 的衔接（已完成）
方案 B（合并群集 C）= 把 `hasNormality` 族的 `R11-ABNORMAL / R14-NORMAL / R17-PERREGION` 统一为单一 `rule_id` **`R17-NORMALITY`**，同时它们共享 `kg_relation="hasNormality"`。这作为"图谱归类"的**第一个具体落地动作**已实施（见 `engine.py` `_r17_cross_region`；回归测试 `test_context_logic_rules.py` / `test_radiology_errors.py` 已同步）。下一步可将 `kg_relation` 元数据增量落到全体规则，使前端按图谱维度分组。

## 六、兼容性说明
- `rule_id` 全程保留，ignores / 样本库 / 前端过滤不受影响（B 合并仅涉及 3 个兜底子规则，已在《重复分析》中说明 ignores 失效范围）。
- 新增 `kg_relation` 为**纯增量元数据**，旧数据缺该字段时前端按 `rule_id` 前缀兜底即可。
- 不需要改 `anatomy_lexicon.py` / `zh_ner.py`——图谱本体已经够用，本方案只是**把规则挂到已有本体上**。
